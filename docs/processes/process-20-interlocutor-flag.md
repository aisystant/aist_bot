# P-20 Свободный чат через агента платформы (флаг, РП-262 Ф4)

> Бот остаётся окном: для каждого, кто прошёл проверку подписки, вопрос в свободном чате уходит в агента платформы
> (программа `iwe-interlocutor`) вместе с пропуском самого человека, а бот показывает готовый
> ответ. Права проверяет шлюз, роль и инструменты определяет агент. Прежний путь
> (`handle_question_with_tools`) остаётся запасным до этапа 6.

## Флаг

| Переменная | Смысл |
|---|---|
| `INTERLOCUTOR_URL` | адрес `POST /v1/turn` агента; пусто = выключено для всех |
| `INTERLOCUTOR_THREAD_MODE` | `1` = выпуск А (РП-262 Ф10): нить разговора хранит агент; любое другое значение или пусто = прежнее поведение |

Список номеров Telegram (`INTERLOCUTOR_TG_IDS`) убран 20.11.2026 по решению пилота: аккаунт владельца работает как у всех. Агент отвечает каждому, кто прошёл проверку подписки в `enter`; бесплатные роли без этой проверки остаются на прежнем пути.

Читается из окружения при каждом вопросе: включение и откат без выкладки кода (убрать значение).

## Ход

1. `states/common/consultation.py::enter` для вопроса (не «Подробнее») зовёт
   `_answer_via_interlocutor` раньше быстрых ответов (они перехватывали вопросы).
2. `engines/shared/interlocutor_client.py::ask` берёт пропуск человека
   (`gateway_mcp.access_token_for`), отправляет вопрос, язык и последние 5 пар истории.
3. Ответ с кодом `answer` показывается с двумя источниками и пишется в историю диалога.
4. Если агент вернул `fallback_allowed: false` (ключ человека к модели отклонён поставщиком,
   РП-262 Ф4, 20.11.2026), бот показывает текст агента и не передаёт вопрос прежнему пути:
   прежний путь ответил бы за счёт платформы. Такое сообщение в историю диалога не пишется.
5. Любой другой исход (нужен вход, не успел, источник недоступен, сеть, нет пропуска) возвращает
   управление прежнему пути без сообщения об ошибке пользователю.

## Выпуск А: нить у агента (РП-262 Ф10, `INTERLOCUTOR_THREAD_MODE=1`)

Условие включения в пилотном боте: **один экземпляр бота** (замок по чату действует только внутри процесса; поколений нити пока нет, это Ф9).

Классы исхода одного хода (`engines/shared/interlocutor_client.py::turn`):

| Класс | Когда | Что делает окно |
|---|---|---|
| `answer` | исход `answer` с текстом | показывает ответ и кнопку «Забыть разговор»; копию пары пока пишет (откат флагом) |
| `agent_message` | текст с `fallback_allowed=false` | показывает один раз, не повторяет, не запоминает |
| `no_pass` | человек не входил, `need_login`, HTTP 401 или 403 | прежний путь с историей, под ответом приглашение войти аккаунтом МИМ |
| `retriable` | сеть, таймаут, HTTP 429 и 5xx, исходы `tool_timeout` и `source_unavailable`, а также вошедший человек, чей пропуск сейчас не удалось обновить | один повтор с тем же `turn_id` через 1 с; снова сбой: «Помощник сейчас недоступен», бот сам не отвечает |
| `error` | прочие HTTP 4xx (в том числе 409), неожиданный исход или тело | не повторяет, «Помощник сейчас недоступен», бот сам не отвечает |

- Ключ повтора: `{chat_id}:m{message_id}` для сообщения, `{chat_id}:c{callback_id}` для нажатия; агент по тому же ключу и тому же тексту возвращает записанный ход (`service.py`, повтор по `turn_id`), по другому тексту отвечает 409.
- Историю (`history`) бот агенту не шлёт. Бесплатные роли и «Подробнее» остаются на прежнем пути с историей.
- Нить стирается запросом `DELETE /v1/thread` при выходе из консультации, при таймауте сессии (15 мин, перед новым вопросом), при «Завершить» и по кнопке «Забыть разговор». Стирание идёт только если агент в этом разговоре отвечал (метка `agent_thread_live` в контексте сессии; ответы прежнего пути её не ставят). Если запрос не прошёл, ставится метка `agent_thread_dirty`: следующий вопрос сначала повторяет стирание, а нить без этого живёт до 30 минут (срок агента). Кнопка «Забыть разговор» после неудачи остаётся, текст честно говорит о сроке.
- Замок по чату: ход и стирание одного человека не пересекаются в пределах одного процесса бота.
- Простой текст в главном меню (после /start) уходит в консультацию, пока режим включён.
- Счётчики: таблица `interlocutor_stats` (день, класс, число, сумма времени); классы `turn`, `answer`, `agent_message`, `no_pass`, `retry`, `unavailable`, `error`, `forget_forgotten`, `forget_refused`, `forget_failed`. Тексты, пропуска и номера чатов не пишутся. Таблица создаётся при старте (миграция 053); где у роли бота нет права создавать таблицы, её создаёт владелец базы, без неё счётчик пишет предупреждение в журнал и ответы людям не страдают.
- Откат: убрать `INTERLOCUTOR_THREAD_MODE` и перезапустить бот; история снова уходит агенту, запасной путь работает.
- Не входит в выпуск А: защита от повторной доставки Telegram-обновления (ответ может прийти дважды, как и раньше), поколения нити для нескольких экземпляров бота (Ф9), удаление копии у платных (выпуск Б).

## Что не делается в этом этапе

- Кнопки обратной связи и запись в `qa` для ответов агента (агент не знает про них).
- Роли бота (навигатор, диагност) и тарифные промпты: роль агента берёт у шлюза.
- Отдельного включения по людям нет: флаг общий для всех подписчиков (решение пилота 20.11.2026).

## Безопасность

Пропуск идёт только в заголовке и не пишется в журнал; в журнал бота пишутся код исхода и
длительность, без вопросов и ответов. Тесты: `tests/test_interlocutor_client.py`, `tests/test_interlocutor_thread_mode.py`.
