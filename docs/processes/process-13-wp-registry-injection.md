# Процесс 13 — Инжекция реестра РП в ответ бота (WP-411 Ф7)

> **Категория:** Процесс (внутренняя логика, наблюдаема как поведение, не экран).
> **Зачем:** на вопрос «какие мои РП?» бот сочинял несуществующие рабочие
> продукты. Реестр (`docs/WP-REGISTRY.md`) не попадал в контекст модели.

## Проблема

`assemble_context` (контекст-пайплайн консультации) реестр РП не загружает.
`personal_search` его не находит: файл помечен `<!-- index-health: skip -->` и
намеренно исключён из семантического индекса (каталог 263+ строк растёт
линейно). При пустом контексте Claude Sonnet падает в параметрическую память и
выдумывает правдоподобные названия проектов.

## Решение (вариант В — детерминированный fetch по пути)

Не семантический поиск, а прямое чтение файла из репозитория пользователя.

### Поток

1. `engines/shared/wp_query_detector.is_wp_query(question)` — классифицирует
   вопрос как «про мои РП»:
   - **Strong** («мои рп», «мой реестр», «wp-registry»…) → всегда да;
   - **Negation** (тематическое «что такое рп», «как устроена»…) → нет;
   - **Weak** (слово-РП + маркер списка «активные/сколько») → да ТОЛЬКО при
     личном сигнале («мои», «у меня»…).
2. `consultation_tools.get_wp_registry(telegram_user_id)` (в
   `handle_question_with_tools`, после `get_tools_for_tier`, перед вызовом
   Claude, под `asyncio.wait_for(5s)`):
   - `github_oauth.get_strategy_repo` → `github_strategy.read_file("docs/WP-REGISTRY.md")`
     (паттерн `get_personal_claude_md`, кэш 5 мин);
   - `parse_active_registry` оставляет активные строки (статус 🔄/⏳, без
     `~~strikethrough~~`), берёт `# + P + Название + статус`.
3. Инжекция в `system_prompt`:
   - реестр получен → секция «РЕЕСТР РАБОЧИХ ПРОДУКТОВ … отвечай ТОЛЬКО из списка»;
   - реестр пуст / нет `strategy_repo` → `<no_wp_data/>` + hard rule «не выдумывать РП».

### Гейт — strategy_repo, не ЦД

Реестр живёт в GitHub (`strategy_repo`), это ось, независимая от ЦД. Гейтить
по `has_digital_twin` нельзя (T3 = github без ЦД тоже имеет реестр).
`get_wp_registry` сам возвращает `""` при отсутствии `strategy_repo` —
обычный пользователь без governance-репо честно получает «нет доступа», а не
выдуманный список.

## Граница знаний

`<no_wp_data/>` — частный случай правила #1 «ГРАНИЦА ЗНАНИЙ» (см. CLAUDE.md §10
Anti-hallucination): нет реальных данных → честный отказ, не домысел.
