# P-17 GitHub App Install — Privacy Enforcement

> После установки GitHub App (`/connect_guide`) колбэк проверяет видимость выбранного репозитория и принудительно переключает публичный репозиторий на приватный. При недостатке прав у App — явное предупреждение пользователю вместо тихого "всё готово".

---

## 1. Зачем

`/connect_guide` не создаёт репозиторий сам — отправляет пользователя на страницу установки GitHub App, где пользователь вручную создаёт репозиторий `personal-guide` в интерфейсе GitHub. Приватность там не выставляется автоматически: аудит (WP-527, 04.09.2026) нашёл 6 из 11 проверенных `personal-guide`-репозиториев публичными, с личными данными участника.

Решение пилота: создание любого репозитория в IWE обязано быть приватным для новичков.

## 2. Как работает

**Файлы:** `clients/github_app.py` (`set_repo_private`), `oauth_server.py` (`github_app_callback_handler`).

`get_installation_repos()` уже возвращает поле `private` в ответе GitHub API `/installation/repositories` — дополнительный запрос не нужен. В колбэке:

1. `selected_repo = repos[0] if repos else None` — тот же репозиторий, из которого берётся `repo_full_name`.
2. Если `selected_repo["private"] is False` → вызов `set_repo_private(installation_id, repo_full_name)` (PATCH `/repos/{full_name}` с `{"private": true}`, требует permission `Administration: write` у App).
3. Успех → лог `INFO`, пользователь ничего не видит (репозиторий уже приватный к моменту показа результата).
4. Отказ (403/иная ошибка) → лог `WARNING` с телом ответа, пользователю добавляется явное предупреждение (в Telegram-сообщении и на HTML success-странице) со ссылкой на настройки репозитория.

## 3. Известное ограничение

**Administration:write — манифест ≠ установка.** Манифест App `aisystant-knowledge` (id 3261992, `gh api apps/aisystant-knowledge`) объявляет `administration:write` с 2026-08-19. Но право, объявленное в манифесте, ещё не значит, что оно разрешено на КОНКРЕТНОЙ установке App — GitHub требует, чтобы владелец установки вручную принял апгрейд прав, если установка создана раньше, чем право появилось в манифесте. Пока это не сделано для конкретной установки — `set_repo_private` для неё вернёт `False` (403), и пользователь получит предупреждение вместо автоматического исправления. Это ожидаемое поведение (fail-safe: явное предупреждение вместо тихого «всё готово»), не баг. Эмпирическая проверка (реальный вызов `set_repo_private` через prod-окружение) на момент написания не проводилась — peer-сессия РП527 04.09 (Кими) эскалировала это пилоту.

**Edge-case `private: None`.** Условие `selected_repo["private"] is False` (шаг 2 выше) требует буквально `False` — если GitHub API в каком-то состоянии вернёт `None`/отсутствие поля вместо `bool`, репозиторий останется публичным БЕЗ предупреждения (ветка if не сработает, `privacy_note` не выставится). Не воспроизведено, но не исключено (peer-review, Кими, 04.09) — если увидите публичный `personal-guide`-репо без предупреждения в логах, проверить этот путь первым.
