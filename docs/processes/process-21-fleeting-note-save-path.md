# P-21 Единая запись быстрой заметки

> Заметка, набранная с точкой, пересланная, надиктованная голосом или продиктованная Siri, записывается одной и той же функцией: те же проверки, тот же файл, пометка источника, один след для платформы, одна строка замера.

---

## Обзор

| Параметр | Значение |
|----------|----------|
| Тип | Процесс (writer в репозиторий пользователя + след на платформу) |
| Источник | WP-384, решение пилота 28.11.2026 (путь Б из проверки Fable) |

| Вызывающий код | `handlers/github.py` (`.текст`, пересылка), `handlers/voice.py` (голос), `oauth_server.py::notes_shortcut_handler` (Siri) |
| Клиент GitHub | `clients/github_api.py::GitHubNotesClient` |
| Сценарии | `scenario-03-16-github.md`, `scenario-02-22-voice.md`, `scenario-03-41-siri-notes.md` |

---

## 1. Функции

| Функция | Что делает |
|---------|-----------|
| `notes_blocker(chat_id)` | Почему заметку нельзя записать: нет доступа к заметкам → не подключён GitHub → не выбран репозиторий. `None` — можно |
| `write_note(chat_id, text, source, message_id=None)` | Дописывает заметку в `fleeting-notes.md`, оставляет след, пишет строку замера. Проверок не делает |
| `save_fleeting_note(...)` | `notes_blocker` + `write_note`; для голоса и Siri, где между ними ничего нет |

`NoteSource`: `text` (без пометки, как раньше), `voice` («· голос»), `siri` («· Siri»). Пометка стоит в строке даты заметки: `<sub>28 ноя, 10:24 · голос</sub>`.

Обработчик с точкой держит прежний порядок: сначала `notes_blocker` (до ожидания пересылки у голой точки), потом склейка с ответом или пересылкой, потом `write_note`. Ответы пользователю и платная стена не менялись.

---

## 2. Запись и отмена

- `GitHubNotesClient.append_note` фиксирует адрес, время и случайный номер операции один раз; внутренние повторы сохраняют их. В файле начало и конец блока отмечены этим номером. Отпечаток считается по физическим строкам, включая многострочные заголовок и тело.
- Под «Записано» у **голосовой** заметки кнопка «↩️ Отменить». Ссылка имеет версию, номер операции и два отпечатка SHA-256 по 12 знаков: содержимого и адреса (репозиторий, файл, ветка). Данные кнопки занимают 63 байта при пределе Telegram 64. `remove_note_block` удаляет только единственный неизменённый блок с этим номером по тому же адресу; конфликт версии (409) повторяется до 3 раз. Прежние ссылки только с отпечатком и длиной отклоняются без удаления.
- Заметку, изменённую после записи или уже удалённую, не трогаем: «Не нашёл эту заметку в файле».
- След `bot_note` на платформе при отмене не удаляется (открытое).

---

## 3. След для платформы (WP-427, датчик `bot_note`)

`capture_note_trace` передаёт текст и ссылку на строку в репозитории через шлюз; в содержимое добавлено поле `source`. Ключ повторной доставки — `note_<номер операции>`: повтор одной записи сохраняет ключ, две одинаковые заметки Siri имеют разные ключи. Старый прямой вызов с номером Telegram-сообщения использует его как запасной ключ. Сбой следа заметку не ломает. Размер содержимого до 64 КиБ, больше — только ссылка. Если после неопределённого ответа GitHub найдена прежняя операция с другим содержимым, повтор передаёт только ссылку, не выдаёт новый текст за записанный и не создаёт кнопку отмены для изменённого блока.

---

## 4. Очередь повторов

Текст и Siri при сбое используют очередь в памяти по расписанию (`core/scheduler.py`). Повтор сохраняет исходные текст, источник, номер сообщения, время, адрес и номер операции; заново проверяет доступ к заметкам. Успех проходит тот же завершающий вызов, что первоначальная запись: след и строка замера не пропускаются. Одна попытка (`_write_note`) очередь не меняет; `retry_pending` ограничивает повторы и не размножает записи. Очередь теряется при перезапуске; на пилотном боте планировщик выключен.

Голос повторяется через постоянную запись операции и кнопку у исходного сообщения, с выключенной очередью в памяти. При новом запуске после сбоя право обработки получает один работник; прежний адрес, время и выбор «заметка / вопрос» сохраняются. До записи GitHub сохраняется отпечаток полного блока, уже объединённого с пересылкой или ответом. Найденный неизменённый блок сохраняет кнопку отмены даже после потери временной пересылки; след тогда передаётся только ссылкой. Другой текст повтора не создаёт новый блок с прежним номером. Перед добавлением GitHub проверяется номер операции: потерянный ответ об успешной записи не создаёт второй блок. Сама таблица операций не хранит текст и аудио.

---

## 5. Замеры

Одна строка в журнале на попытку: `[note-metric] source=<text|voice|siri> outcome=<saved|no_access|no_github|no_repo|reconnect|failed> chars=<n> ms=<n>`. Текста заметки в строке нет. Для голоса дополнительно `[voice-metric]` (исход, длительность, время распознавания) и отрезок `voice.stt` в трассе запроса.

---

## 6. Открытое

- Запись идёт токеном пользователя сразу, без показа цели и содержимого и без разового разрешения. Это расхождение с правилом РП-262 (К4, этап 2 Ф4); цель — запись через шлюз платформы с подтверждением, для Siri «без рук» - постоянное согласие с отменой.
- Замеры только в журнале; в событийный шлюз они не уходят (там нужна схема события).
- Заметки хранятся и обрабатываются в боте; перенос на службу платформы - следующий шаг пути (РП-384, вариант В).
