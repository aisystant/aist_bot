# 03.41 Сценарий: заметки голосом через Siri (/siri)

> WP-384 / DP.SC.178. Команда айфона «Заметка в IWE»: Siri слушает мысль, текст уходит в бот по личному ключу и ложится туда же, куда заметки с точкой (с пометкой «Siri»); Siri вслух говорит, куда записано.

---

## Обзор

| Параметр | Значение |
|----------|----------|
| Триггер | `/siri` в личном чате (ключ один раз и шаги настройки); `/siri new` - заменить ключ; `/siri off` - отключить |
| Приём заметок | `POST /api/notes`, заголовок `X-IWE-Api-Key`, тело `{"text": "..."}` |
| Результат | Блок в `fleeting-notes.md` репозитория заметок (в строке даты «· Siri»); ответ `{"ok", "say", "url"}`, `say` произносит Siri |
| Файлы логики | `handlers/siri.py`, `oauth_server.py::notes_shortcut_handler`, `core/fleeting_notes.py` (процесс P-21), `db/queries/iwe_extension.py` |
| Обещание | DP.SC.178 |

---

## Предусловия

0. Заметки через Siri включены для этого пользователя: разработчик бота (`DEVELOPER_CHAT_ID`) или чат из `VOICE_ALLOWED_CHAT_IDS` (`*` - все). Остальным `/siri` отвечает, что функция в закрытой проверке, и показывает их номер в Telegram, по которому их можно добавить в список.
1. Пользователь привязал аккаунт Aisystant (`/link`).
2. Для записи - те же условия, что у «.текст»: доступ к заметкам, подключённый GitHub, выбранный репозиторий.
3. Выдача, замена и отключение ключа выполняются только в личном чате. В группе или канале команда показывает ссылку на личный диалог и не читает и не меняет ключи.

---

## Поток

1. **/siri.** Бот выдаёт личный ключ только для заметок (служба `iwe_notes_shortcut`, область `notes`; ключ браузерного расширения из `/iwe` здесь не подходит) и пошаговую настройку команды айфона: «Продиктовать текст» → «Получить содержимое URL» (POST, заголовок ключа, JSON с полем `text`) → «Получить значение из словаря» (`say`) → «Произнести текст». В базе хранится **только отпечаток ключа** (SHA-256), сам ключ восстановить нельзя, поэтому он **показывается один раз**. Повторный `/siri` показывает шаги без ключа; `/siri new` выдаёт новый ключ, старый перестаёт работать; `/siri off` отключает ключ. Ключ, выданный до этой версии (хранился зашифрованным), недействителен: нужен `/siri new`.
2. **«Привет, Siri, Заметка в IWE».** Айфон сам распознаёт речь (звук в бот не уходит) и отправляет текст.
3. **Приём.** Бот считает неверные ключи по адресу клиента (последняя запись `X-Forwarded-For`): после 20 неверных за 10 минут отвечает 429, не обращаясь к базе. Дальше проверяет ключ одним запросом по отпечатку, частоту (не чаще раза в 5 сек на аккаунт), длину (до 4000 знаков), находит чат владельца и сохраняет заметку теми же проверками, что «.текст» (`core/fleeting_notes.save_fleeting_note`, источник `siri`). Текст заметки в журнал не пишется; запись попытки - строка `[note-metric] source=siri …`.
4. **Ответ Siri.** «Записано в быстрые заметки, репозиторий <имя>.» или причина отказа. В Telegram бот отдельно не пишет: сообщения по своей инициативе идут только через центр уведомлений. След заметки для платформы (`bot_note`) оставляется, как у остальных.

Каждый отдельный запрос заметки получает собственный постоянный номер операции: одинаковые тексты в одну минуту остаются разными заметками. Внутренний повтор неудавшейся записи сохраняет этот номер и исходный адрес назначения.

## Режим отказа

| Ситуация | Код | Что говорит Siri |
|----------|-----|------------------|
| Нет ключа или ключ не подошёл | 401 | «Ключ не подошёл. Получите новый в боте командой сири.» |
| 20 неверных ключей за 10 минут с одного адреса | 429 | «Слишком много неверных ключей. Подождите несколько минут.» |
| Чаще раза в 5 сек | 429 | «Слишком часто. Подождите несколько секунд.» |
| Пустой текст или не JSON | 400 | «Не расслышал заметку. Повторите.» / «Не понял запрос.» |
| Длиннее 4000 знаков | 413 | «Заметка слишком длинная. Разбейте на части.» |
| Аккаунт не связан с ботом | 404 | «Аккаунт не привязан к боту.» |
| Заметки через Siri не включены для пользователя | 403 | «Заметки через Siri пока недоступны.» |
| Нет доступа, GitHub, репозитория, нужен повторный вход, сбой записи | 200, `ok: false` | Причина и что сделать в боте |

---

## Не входит

- Вопросы к Наставнику через Siri (только заметки).
- Сообщение в чат о записи от Siri.
- Отмена заметки, записанной через Siri (кнопка «Отменить» есть у голосовых в боте).
- Готовый файл команды для установки одной кнопкой (пока настройка вручную по шагам из `/siri`).
