# Сценарий 03-30: /remind — Пользовательские напоминания

**Вид:** C (Микро) — одна команда → один ответ, без FSM  
**Команда:** `/remind`, `/remind list`, `/remind cancel <id>`  
**Handler:** `handlers/remind.py`  
**Сервис:** DP.SC.134 (Notification Dispatcher), DP.ROLE.044 (WP-320 Ф3)

## Описание

Позволяет пользователю создать личное напоминание с произвольным текстом и временем.
Scheduler в `core/scheduler.py` подбирает записи через `check_reminders()` каждую минуту и доставляет через `send_user_reminder()`.

## Точки входа

| Команда | Поведение |
|---------|-----------|
| `/remind текст` | Создать напоминание через 1 час (по умолчанию) |
| `/remind текст [время]` | Создать с явным временем |
| `/remind list` | Список активных напоминаний |
| `/remind cancel <id>` | Отменить напоминание по ID |
| `/remind` | Показать справку по формату |

## Форматы времени

| Шаблон | Пример |
|--------|--------|
| через N мин/часов/дней | `через 2 часа`, `через 30 минут` |
| в HH:MM | `в 15:30` |
| завтра [в HH:MM] | `завтра`, `завтра в 9:00` |
| DD Месяц [HH:MM] | `17 мая 15:00`, `3 июня` |
| ISO | `2026-05-17 15:00` |

## Источники данных

- **Запись:** `learning.reminder` (reminder_type='custom', text=текст пользователя)
- **Доставка:** `core/scheduler.py:check_reminders()` → `send_user_reminder()`
- **Идемпотентность:** `public.notification_log` (ключ `user_remind:{chat_id}:{id}`)

## Ответы пользователю

- Создание: подтверждение с текстом, временем (UTC) и ID для отмены
- List: перечень активных с датами и ID
- Cancel: «Напоминание N отменено» / «не найдено»
- Ошибка парсинга: предложить ввести снова

## Связь с MCP-tool

Тот же `learning.reminder` используется `send_telegram_message` (MCP-tool в mcp.aisystant.com, DP.SC.134 consumer: Claude-агент). Оба потребителя обслуживаются одним scheduler.
