# 03.36 `/mentor_stream` — регистрация группы за потоком

> Наставник или пилот регистрирует группу потока (по коду вида S1-2026.3-T), чтобы бот начал
> собирать её переписку в архив. Разбор решения:
> `DS-my-strategy/inbox/WP-578/DRR-f2-telegram-bridge.md` §3.

---

## Обзор

| Параметр | Значение |
|----------|----------|
| Команда | `/mentor_stream <STREAM_ID>`, только в группе/супергруппе |
| Тип | Микро (C) — одна команда, один ответ |
| Файлы | [`handlers/mentorship.py`](../../../handlers/mentorship.py), [`db/queries/mentorship.py`](../../../db/queries/mentorship.py) |
| БД | Отдельный Neon-проект (не `aisystant`), роль `mentorship_app`, таблица `stream_chat` |
| Доступ | Только читатель потока (`stream_reader.role IN ('mentor','pilot')`) — проверяется и на уровне БД (RLS `WITH CHECK`), и заранее в коде для дружелюбного сообщения об ошибке |

---

## 1. Команда

```
Наставник (в группе потока): /mentor_stream S1-2026.3-T
```

Код потока — полный, из учебной платформы (год, набор, тип), не сокращение `S1`.

### Кто получает ответ (Ф9)

Бот сначала проверяет, кто вызвал команду, и только потом отвечает. Публичный ответ в группу
получает только успешная регистрация; всё остальное — либо тишина, либо личное сообщение
наставнику.

**Посторонний — бот молчит совсем** (ни в группе, ни в личке): нет привязанного аккаунта платформы,
аккаунт не числится читателем ни одного потока, модуль наставничества отключён. Снаружи причины
неразличимы; в журнале бота отключённый модуль оставляет предупреждение, обычный посторонний — нет.

### Ответы бота (наставнику или пилоту)

- Без аргумента — **в личку**: «Укажи код потока: /mentor_stream <код>. Твои потоки: S1-2026.3-T, S2-2026.4-T.» (коды берутся из `stream_reader`, не из текста). В группе тишина.
- Поток не из его списка — **в личку**: «Не удалось: вы не числитесь наставником или пилотом потока X. Твои потоки: …»
- Уже зарегистрирован за тем же потоком — **в группу**: «Группа уже зарегистрирована за потоком S1-2026.3-T.» (идемпотентно, без побочных эффектов)
- Успех — **в группу**: «✅ Группа зарегистрирована за потоком S1-2026.3-T.»
- Права пропали между проверкой и записью (редкая гонка) — **в личку**.

## 2. Перерегистрация на другой поток

Повторный вызов с другим `STREAM_ID` в той же группе помечает старую
регистрацию `superseded_at` (аудируемо, история сохранена в `stream_chat`, не
теряется) и создаёт новую активную строку. Отдельного подтверждения бот не
спрашивает — решение принято на уровне архитектуры: регистрация делается
редко и осознанно, командой, а не случайным кликом.

## 3. Известные ограничения

- Право администратора группы в Telegram НЕ учитывается — только
  принадлежность к `stream_reader`. Обычный админ группы, не являющийся
  наставником/пилотом потока, команду выполнить не может.
- Второй бот в группу не заводится (Ф0) — регистрация всегда идёт через
  того же бота, что уже присутствует в потоке.
- Наставник без привязанного к боту аккаунта платформы получает тишину, как посторонний: бот не может
  отличить его от участника. Сначала привязка аккаунта (`/link`); по данным Ф10 у части преподавателей
  в `stream_reader` нет внешнего идентификатора.
- Личка с ботом должна быть открыта заранее (наставник хотя бы раз писал боту): иначе Телеграм не даёт
  боту написать первым, подсказка не придёт и не придёт нигде; в журнале останется предупреждение.
  Требование «открыть личку» — часть онбординга наставников, публичного резервного сигнала нет
  (решение пилота 21.09).
