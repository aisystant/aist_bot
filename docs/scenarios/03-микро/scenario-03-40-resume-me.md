# 03.40 `/resume_me` — снова включить сбор своих сообщений

> Пара к `/erase_me` (03.39). Участник, который раньше удалил свои данные,
> снимает свой отказ: его новые сообщения в закрытых чатах снова попадают в
> архив «Аналитика чата». Удалённые сообщения не возвращаются. Решение пилота
> 03.11 после живой проверки удаления. Бот — тонкий клиент: отказ снимает
> сервис (`POST /participants/{id}/resume`, CONTRACT.md).

---

## Обзор

| Параметр | Значение |
|----------|----------|
| Команда | `/resume_me` — только личка с ботом |
| Тип | Микро (C) — одна команда, одно сообщение с кнопками, как 03.39 |
| Файлы | [`handlers/chat_analyst.py`](../../../handlers/chat_analyst.py) — `cmd_resume_me`, `cb_resume_me`, общая `_run_self_action`; [`clients/chat_analyst.py`](../../../clients/chat_analyst.py) — `resume_participant` |
| Доступ | Любой человек; меняется только его собственный отказ (`callback.from_user.id`) |

## Поток

1. Участник пишет `/resume_me` в личке.
2. Бот объясняет: новые сообщения снова будут попадать в архив и сводки, удалённые раньше не вернутся; ссылка на условия; кнопки «Включить сбор» / «Отмена».
3. «Отмена» → «Отменено, ничего не изменилось».
4. «Включить сбор» → вызов сервиса с номером нажавшего (до трёх попыток) → «Сбор ваших сообщений снова включён».
5. Сервис не подтвердил → «Не удалось подтвердить, что сбор включён… повтор безопасен».

Граничные случаи — те же, что у 03.39: в группе бот молчит; повтор безопасен (ответ тот же, был отказ или нет); опоздавшее нажатие и неудачное снятие кнопок действие не отменяют.
