# Сценарий 03-28: /edit_time

**Категория:** микро (вид C, список + inline-действия)
**Что делает:** показывает последние 14 записей slot_logged с возможностью редактировать или удалять.
**WP:** WP-310 Ф13d

## Поток

```
/edit_time
→ Список последних 14 записей:
  «Последние записи slot_logged:
   📅 2026-05-15  ⏱ 1.5 ч  (active)
   📅 2026-05-14  ⏱ 1.4 ч  (backfill)
   ...»
  [✏️ 2026-05-15 1.5ч] [🗑]
  [✏️ 2026-05-14 1.4ч] [🗑]
  ...
```

### Редактирование [✏️]
```
→ «Текущее: 1.5 ч. Введи новое значение (0.1 до 24):»
→ Пользователь вводит число
→ «✅ Обновлено: N ч.»
```

### Удаление [🗑]
```
→ «Удалить запись YYYY-MM-DD N ч?»
  [Да, удалить] [Отмена]
→ Да: «🗑 Удалено.»
→ Отмена: «Отменено.»
```

### Нет записей
```
→ «Нет записей slot_logged. Используй /slot чтобы добавить.»
```

## Безопасность

**Privacy guard:** все UPDATE и DELETE включают `AND user_id = $1`.
Пользователь не может изменить чужие записи, даже зная event_id.

## Что изменяет

- `UPDATE`: только поле `hours` в JSONB (`jsonb_set`). Поля `source`/`confidence`/`batch_id` сохраняются — audit trail остаётся.
- `DELETE`: удаляет всю запись из `development.user_events`.

## FSM

Использует `EditTimeStates.waiting_new_value` для получения нового значения часов.
Стейт также используется для custom-ввода в /slot.
