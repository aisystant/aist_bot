# 01.01 Сценарий Марафона

> Полное описание процесса 14-дневной программы обучения с точки зрения потока сообщений, данных и прогресса.

---

## Обзор

| Параметр | Значение |
|----------|----------|
| Длительность | 14 дней |
| Тем в день | 2 (Урок + Задание) |
| Всего тем | 28 |
| Макс. тем в день | 4 (для наверстывания) |
| Участник | Ученик |

## 1. Онбординг (Регистрация)

### Запуск

Команда `/start` запускает 8-шаговый онбординг.

### Шаги онбординга

| Шаг | Сообщение бота | Тип | Что сохраняется |
|-----|----------------|-----|-----------------|
| 1 | Как вас зовут? | Запрос данных | `name` |
| 2 | Чем вы занимаетесь? | Запрос данных | `occupation` |
| 3 | Какие интересы/хобби? | Запрос данных | `interests` (JSON) |
| 4 | Что для вас важно в жизни? | Запрос данных | `motivation` |
| 5 | Что вы хотите изменить? | Запрос данных | `goals` |
| 6 | Сколько минут на одну тему? | Запрос данных | `study_duration` (5/15/25) |
| 7 | Во сколько присылать напоминания? | Запрос данных | `schedule_time` (HH:MM) |
| 8 | Когда начать марафон? | Запрос данных | `marathon_start_date` |

### Завершение онбординга

```
Бот → Сводка: Профиль
      "Ваш профиль: {name}, {occupation}..."
      [Кнопка: Подтвердить]

Ученик → Нажимает "Подтвердить"

Бот → Служебное: Подтверждение
      "Профиль сохранён! Используйте /learn для начала."
```

### Сохраняемые данные

**Таблица `interns`:**
```
chat_id, name, occupation, interests, motivation, goals,
study_duration, schedule_time, marathon_start_date,
language, onboarding_completed = TRUE,
marathon_status = 'not_started'
```

## 2. Структура дня Марафона

### Формула

```
День N = Урок (теория) + Задание (практика)
```

Каждый день содержит ровно 2 темы:
- **Чётный индекс** (0, 2, 4...) — Урок
- **Нечётный индекс** (1, 3, 5...) — Задание

### Синхронизация состояния при запуске марафона (обновлено 23 мая 2026)

При команде `/marathon_start` (или запуске через меню):

1. **Обновление объекта ученика в памяти:** `intern.marathon_status = "started"`
2. **Синхронизация с БД:** вызов `update_intern()` — это ОБЯЗАТЕЛЬНО пишет изменение в таблицу `interns`
3. **Последующие команды** (напр. `/profile`) читают актуальное состояние из БД

**Правило:** Всякий раз, когда изменяется пользовательское состояние (`marathon_status`, `is_onboarded`, `bloom_level`), обязателен немедленный вызов `update_intern()`. Пропуск синхронизации приводит к расхождению памяти и БД, из-за чего `/profile` показывает устаревшие данные.

### Пример структуры

| День | Индексы тем | Урок | Задание |
|------|-------------|------|---------|
| 1 | 0, 1 | Четыре состояния | Моё текущее состояние |
| 2 | 2, 3 | Практики развития | Слот для практики |
| ... | ... | ... | ... |
| 14 | 26, 27 | Итоговый урок | Итоговое задание |

## 3. Полная последовательность сообщений дня

### Диаграмма потока

```
[Ученик]                              [Бот]

/learn ─────────────────────────────► Проверка: есть ли доступные темы?
                                      ↓
                                      Материал урока
                                      "📚 День N: {название}"
                                      [теоретический текст]

                                      Вопрос урока (Сложность N)
                                      "💭 {вопрос по теории}"

Ответ на урок (≥20 симв.) ──────────► Служебное: Подтверждение
                                      "✅ Ответ принят"

                                      [Если Сложность ≥ 2 (уровни 2-3)]
                                      Бонусный вопрос (опционально)
                                      "🚀 Хотите вопрос посложнее?"
                                      [Да] [Нет]

[Вариант А: Нет/игнор] ─────────────► Материал задания
                                      "📝 Задание: {название}"
                                      [инструкция к практике]

                                      Запрос данных
                                      "Когда завершите, напишите название РП"

[Вариант Б: Да] ────────────────────► Бонусный вопрос (Сложность N+1)
                                      "🎯 {сложный вопрос}"

Ответ на бонус (≥20 симв.) ─────────► Служебное: Подтверждение
                                      "✅ Бонус засчитан!"

                                      Материал задания
                                      [см. выше]

Ответ на задание (≥3 симв.) ────────► Служебное: Подтверждение
                                      "✅ Практика засчитана!"

                                      Сводка: Статистика
                                      "🎉 День N завершён!"
                                      "Теория ✅ Практика ✅"

                                      [📊 Посмотреть прогресс]  ← кнопка
```

## 4. Все типы сообщений

### От бота к Ученику

| Тип | Подтип | Когда отправляется | Пример |
|-----|--------|-------------------|--------|
| **Материал** | Материал урока | После `/learn`, если следующая тема — урок | Теоретический текст |
| **Материал** | Материал задания | После ответа на урок | Инструкция к практике |
| **Вопрос** | Вопрос урока | Сразу после материала урока | "В чём разница между...?" |
| **Вопрос** | Бонусный вопрос | После ответа на урок (опционально) | "Приведите пример из жизни..." |
| **Обратная связь** | Консультация | На вопрос пользователя | Ответ через MCP |
| **Запрос** | Запрос данных | После материала задания | "Напишите название РП" |
| **Сводка** | Профиль | Команда `/profile` | Информация о профиле |
| **Сводка** | Статистика | Команда `/progress` или после завершения дня | Прогресс по неделям |
| **Служебное** | Подтверждение | После каждого ответа | "✅ Принято" |
| **Служебное** | Ошибка | При ошибке | "⚠️ Технические неполадки" |

### От Ученика к боту

| Тип | FSM-состояние | Валидация | Пример |
|-----|---------------|-----------|--------|
| **Ответ на урок** | `waiting_for_answer` или fallback | ≥20 символов | "Развитие — это..." |
| **Ответ на бонус** | `waiting_for_bonus_answer` | ≥20 символов | "В моей работе это проявляется..." |
| **Ответ на задание** | `waiting_for_work_product` или fallback | ≥3 символа | "Список в заметках" |
| **Вопрос пользователя** | любое (начинается с `?`) | — | "?Что такое собранность?" |

## 7. Особые состояния

### Дневной лимит исчерпан

```
Ученик → /learn (после 4 тем за день)

Бот → Служебное: Подтверждение
      "🎯 Сегодня вы уже прошли 4 темы — это максимум!"
      "Возвращайтесь завтра."
```

### Тема пропущена

```
Ученик → Кнопка [⏭ Пропустить тему] (или текст "пропустить"/"skip")

Бот → Служебное: Подтверждение
      "⏭ Тема пропущена: {название}"
      "Пропущенные темы не засчитываются."
```

Примечание: Кнопка пропуска отображается под вопросом урока и под заданием.

> **Keyboard Policy:** Все Reply-клавиатуры (skip, yes/no) удаляются через `ReplyKeyboardRemove` на каждом пути выхода из стейта. См. `CLAUDE.md § 10.5`.

### Напоминания

| Время | Сообщение |
|-------|-----------|
| schedule_time + 1ч | "⏰ День N марафона ждёт вас! /learn" |
| schedule_time + 3ч | "🔔 Последнее напоминание. Даже 15 минут — это прогресс." |

### Индикация состояния

Каждое сообщение бота, ожидающее ответа, содержит подсказку о текущем состоянии:

```
💭 Вопрос для размышления...

_Напишите ответ в сообщении..._

💬 *Ожидаю:* ваш ответ на вопрос (≥20 символов)
_Чтобы задать вопрос к ИИ, начните сообщение с ?_
```

Для практики:
```
📝 *Когда выполните задание:*...

💬 *Ожидаю:* название рабочего продукта (≥3 символов)
_Чтобы задать вопрос к ИИ, начните сообщение с ?_
```

### Вопросы к ИИ (префикс ?)

Пользователь может задать вопрос к ИИ в любой момент, начав сообщение с `?`:

```
Ученик → ?Что такое состояние хаоса?

Бот → [Консультация через Claude + MCP]
      "Состояние хаоса — это..."
```

Бот обрабатывает вопрос и возвращает пользователя к ожиданию ответа.

### Fallback при потере FSM-состояния

Если FSM-состояние потеряно (перезапуск бота, ошибка), бот восстанавливает контекст:

**Для урока** (теория отправлена, ответ не получен):
```
Ученик → [текст ≥20 символов, не начинается с ? или /]

Бот → ✅ Ответ принят [fallback]
      → Переход к практике
```

**Для практики** (теория пройдена, практика ожидает ответ):
```
Ученик → [текст ≥3 символов, не начинается с ? или /]

Бот → ✅ Практика засчитана [fallback]
      → День завершён
```

## Content Budget Model (DP.D.027)

Генерация уроков и заданий в марафоне подчиняется **Content Budget Model** — 3 независимые оси:

| Ось | Что определяет | Как реализована |
|-----|----------------|-----------------|
| **Ось 1 — Длина** | Целевое число слов | `words = duration × WPM_BASE(60) × BLOOM_MULTIPLIER[bloom]` — `config.calc_words()` |
| **Ось 2 — Глубина** | Стиль (доступный / профессиональный / экспертный) | `BLOOM_INSTRUCTION[bloom]` — отдельная инструкция в system prompt |
| **Ось 3 — Персонализация** | Профиль, assessment state, tier context | `_build_user_profile()` + TIER_PIPELINE |

**Константы:**

```python
WPM_BASE = 60
BLOOM_MULTIPLIER = {1: 1.0, 2: 1.3, 3: 1.7}
BLOOM_INSTRUCTION = {
    1: "Объясни доступно, без терминов. Примеры из повседневной жизни.",
    2: "Используй профессиональную терминологию. Показывай связи между понятиями.",
    3: "Экспертный уровень. Критический анализ, неочевидные аспекты, ссылки на источники.",
}
```

**Правило раздельности:** Длина и глубина НЕ должны смешиваться в одной инструкции. Bloom влияет на объём через множитель (Ось 1) **И** на стиль через инструкцию (Ось 2) — **раздельно**.

**Auto-upgrade bloom:** `BLOOM_AUTO_UPGRADE_AFTER` — bloom-уровень user растёт не от желания, а от демонстрации освоенности (число успешно пройденных тем на текущем уровне).

**Adaptive max_tokens** (§9 CLAUDE.md): `min(words × 1.5, 4096)` — масштабируется под Ось 1, не hardcode 4000.

**Подробнее:** [P-02 §7 Content Budget Model](../../processes/process-02-content-generation.md).

## 11. Новый формат марафона (WP-330, актуально)

> **Статус:** Основной формат с 2026-05-30. Старый SM-формат (секции 2-10) — deprecated, удаление после 2026-07-05.

### Ключевые отличия

| Параметр | Старый SM-формат (deprecated) | Новый формат (WP-330) |
|----------|-------------------------------|----------------------|
| Структура | 28 LLM-тем через SM-состояния | 14 дней × статический контент |
| Контент | Генерируется Haiku/Sonnet per user | Фиксированный текст из `data/marathon-content.json` (4 версии под профиль) |
| Доставка утром | Scheduler → `lesson_practice` → JSON | То же |
| On-demand `/learn` | → `workshop.marathon.lesson` (SM) | → `_deliver_marathon_lesson` (статика) |
| Прогресс | `interns.current_topic_index` | `marathon_progress.current_day` (Neon) |

### Поток (новый)

```
[Ученик]                              [Бот]

/learn ─────────────────────────────► try_deliver_new_marathon()
                                        ↓ читает marathon_progress.current_day
                                        ↓ get_day_text(day, 'lesson', intern)
                                      Урок дня N (статический текст)
                                      [✏️ Перейти к практике]

Кнопка «Перейти к практике» ────────► get_day_text(day, 'practice', intern)
                                      Практика дня N
```

### Версии контента

4 версии под профиль пользователя (routing через `core/marathon_content.py:resolve_variant`):

| study_duration | complexity_level | Ключ |
|---|---|---|
| < 15 мин | 1 | `lesson_short_simple` |
| < 15 мин | ≥ 2 | `lesson_short_complex` |
| ≥ 15 мин | 1 | `lesson_long_simple` |
| ≥ 15 мин | ≥ 2 | `lesson_long_complex` |

Fallback при отсутствии версионного ключа → legacy-ключ `lesson` (≤500 символов).

### Файлы нового формата

| Файл | Назначение |
|------|-----------|
| `handlers/marathon.py` | Старт, доставка урока on-demand, прогресс |
| `core/marathon_content.py` | Загрузчик JSON, routing по профилю |
| `data/marathon-content.json` | Runtime-контент (source: DS-marathon-v2-tseren) |
| `scripts/sync-marathon-content.sh` | Синхронизация авторского файла → data/ |
| `db/queries/marathon_newcomer.py` | Очередь, прогресс, чек-ины |
| `core/scheduler.py` | Утренняя доставка (lesson_practice) |

### Входы в марафон (все переключены на новый формат)

| Точка | Файл | Действие |
|-------|------|---------|
