# 02.22 Сценарий голосового ввода

> WP-384 / DP.SC.178 «Голосовой канал IWE (ввод)».
> Голосовое сообщение в боте → расшифровка → тот же путь, что у набранного текста: по умолчанию заметка как «.текст» (с пометкой «голос» и кнопкой «Отменить»), вопрос Наставнику - если голосовое начинается со слова «вопрос».

---

## Обзор

| Параметр | Значение |
|----------|----------|
| Триггер | Голосовое сообщение в личном чате с ботом |
| Результат | Эхо расшифровки; заметка в `fleeting-notes.md` репозитория заметок (как «.текст», в строке даты «· голос») или ответ Наставника (как «?текст») |
| Файлы логики | `handlers/voice.py`, `handlers/github.py::process_fleeting_note`, `core/fleeting_notes.py` (процесс P-21) |
| Обещание | DP.SC.178 |

---

## Предусловия

0. Голос включён для этого пользователя: разработчик бота (`DEVELOPER_CHAT_ID`) или чат из `VOICE_ALLOWED_CHAT_IDS` (`*` - все). Остальным голосовое обрабатывается как раньше, до голосового канала.
1. Пользователь привязал аккаунт Aisystant (T1+).
2. Дано согласие `voice_processing` (кнопка при первом голосовом; отозвать - `/voice_off`).
3. В окружении бота задан `STT_API_KEY` (по умолчанию провайдер OpenRouter, модель `openai/gpt-4o-mini-transcribe`; меняются переменными `STT_BASE_URL`, `STT_MODEL`).
4. Для заметки - те же условия, что у «.текст»: доступ к заметкам, подключённый GitHub и выбранный репозиторий.

---

## Поток

1. **Голосовое.** Бот не берёт голосовое и оставляет прежнюю обработку, если ждёт ответа пользователя (состояние диалога, ответ в марафоне или ленте, рабочая сессия) или если голосовое - ответ на сообщение самого бота. Длительность не больше `VOICE_MAX_DURATION_SEC` (по умолчанию 60 сек); длиннее - отказ с предложением разбить или написать текстом.
2. **Согласие (первый раз).** Бот отвечает на это голосовое сообщением-согласием: запись распознаёт сервис OpenAI через OpenRouter по их правилам хранения, бот запись не хранит, текст сохраняется заметкой туда же, куда заметки с точкой, копия текста заметки передаётся платформе, как у обычных заметок; слово «вопрос» в начале уводит голосовое к Наставнику, слово «заметка» - точно в заметку; отключить - `/voice_off`. Кнопка «✅ Согласиться» (callback `voice_consent_grant`): после неё **это же голосовое обрабатывается сразу**, повторять не нужно.
3. **Распознавание.** Перед скачиванием бот получает право обработать исходное сообщение по номеру бота, чата и сообщения. Одновременное нажатие и повтор после перезапуска не запускают завершённую обработку снова. Бот скачивает OGG в память и отправляет в `/audio/transcriptions` провайдера; запись не пишется на диск. Голосовой обработчик, запись заметок и общий поиск ответа не пишут расшифровку в журнал. После распознавания бот ещё раз проверяет, не начался ли другой диалог; если начался, предлагает повторить обработку позднее.
4. **Эхо.** «🎤 <расшифровка>».
5. **Заметка (по умолчанию).** Расшифровка (без слова «заметка» в начале, если оно было) передаётся обработчику заметок как «.<расшифровка>» с источником «голос»: доступ, GitHub, репозиторий проверяются там же, в файле в строке даты стоит «· голос», ответ «Записано → ссылка» с кнопкой «↩️ Отменить». Если голосовое было ответом на сообщение, оно склеивается с ним, как у текстовой заметки.
6. **Отмена.** «↩️ Отменить» проверяет постоянный номер операции, отпечаток содержимого и прежний адрес назначения. Другая одинаковая заметка, изменённый текст и заметка в другом репозитории не удаляются. Проверка учитывает все физические строки многострочного текста и работает после перезапуска бота. Кнопки прежнего формата только с отпечатком и длиной считаются устаревшими и ничего не удаляют: по ним нельзя безопасно отличить две одинаковые заметки.
7. **Вопрос («вопрос …»).** Слово «вопрос» в начале отрезается, остаток уходит в машину состояний как «?<вопрос>» (глобальное событие `consultation`, отвечает Наставник). Пользователь без завершённого онбординга получает просьбу задать вопрос текстом.
8. **Замер.** Одна строка `[voice-metric] outcome=… voice_sec=… stt_ms=… chars=…` на голосовое (без текста), отрезок `voice.stt` в трассе запроса; запись заметки даёт строку `[note-metric]`.

## Режим отказа

| Ситуация | Реакция |
|----------|---------|
| Голос не включён для пользователя | Прежняя обработка сообщения |
| Нет аккаунта | Подсказка подключить аккаунт |
| Нет согласия | Ответ-согласие с кнопкой |
| Не задан `STT_API_KEY` | «Голосовые временно недоступны» |
| Хранилище операций недоступно или не подготовлено | Отказ до скачивания и распознавания; кнопка повтора |
| Исходное сообщение уже обрабатывается / завершено | «Ещё обрабатывается» / «Уже обработано», без повторного распознавания |
| Во время распознавания начался другой диалог | Предложение закончить диалог и повторить обработку исходного сообщения |
| Не скачалось голосовое | «Не удалось получить голосовое» |
| Ошибка распознавания | «Не смог распознать, повтори или напиши текстом» |
| Пустая расшифровка | «Скажи ещё раз или напиши текстом» |
| Нет доступа к заметкам, GitHub или репозитория | Те же сообщения, что у «.текст» |
| Вопрос не построен | «Задай его текстом, начав с «?»» |
| Отмена: заметку не нашли / не удалось | «Не нашёл эту заметку в файле…» / «Не получилось отменить. Попробуй ещё раз.» |

## Хранилище операций

В основной базе бота хранится `development.voice_operation`: постоянный номер операции, исходные номера бота/чата/сообщения, состояние, ограниченное время владения, адрес назначения и результат без текста. Аудио и расшифровка в эту таблицу не записываются. Работник продлевает владение; после его сбоя другой запуск получает ту же операцию, а прежний работник уже не может завершить её. Неудавшуюся голосовую запись повторяют кнопкой у исходного сообщения; отдельная очередь в памяти для неё выключена. В записи GitHub тот же номер предотвращает повторное добавление после потерянного ответа сервера.

Миграцию `055_voice_operations` выполняет владелец базы с `--grant-to <фактическая роль бота>`: роли выдаются только чтение и изменение записей, без прав владельца или создания таблиц. Запуск бота сверяет схему; отказ подготовки выключает только голосовую обработку. При удалении данных пользователя записи операций удаляются по номеру чата.

## Не входит

- Голосовые ответы (озвучка).
- Живой голосовой разговор.
- Записи длиннее 60 сек.
- Голосовые в группах и каналах.
- Удаление следа заметки на платформе при отмене.
