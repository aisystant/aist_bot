## 1. Распознавание вопроса

### Префикс `?` — гарантированный триггер

Пользователь может начать сообщение с `?` чтобы **гарантированно** задать вопрос к ИИ:

```
Пользователь → ?Что такое собранность?

Бот → [Консультация через Claude + MCP]
      "Собранность — это..."

      💬 *Ожидаю:* ваш ответ на вопрос (≥20 символов)
```

**Важно:** После ответа на консультацию бот возвращается к ожиданию ответа на урок/задание. Пользователь может сразу продолжить и написать свой ответ — он будет засчитан.

### Поддерживаемые состояния

| FSM-состояние | После консультации |
|---------------|-------------------|
| `waiting_for_answer` | Возвращается к ожиданию ответа на урок |
| `waiting_for_bonus_answer` | Возвращается к ожиданию ответа на бонус |
| `waiting_for_work_product` | Возвращается к ожиданию РП |
| `waiting_fixation` (Лента) | Возвращается к ожиданию фиксации |

### Intent Detection (автоматический)

Если сообщение НЕ начинается с `?`, бот определяет тип через `detect_intent()`:

**Признаки вопроса:**
- Заканчивается на `?`
- Начинается с вопросительного слова (что, как, почему, why, how, qué...)
- Содержит конструкции: "можно ли", "а что если", "объясни", "скажи"

**Вероятностная оценка (score ≥ 0.7):**

| Признак | Баллы |
|---------|-------|
| Вопросительный знак | +0.5 |
| Вопросительное слово в начале | +0.3 |
| Вопросительные слова в тексте | +0.1 |
| Фразы "что такое", "как работает" | +0.3 |
| Длинный текст без признаков | ×0.5 |

**Примеры:**
```
"Как работает собранность?" → QUESTION (score 0.8)
"Объясни концепцию" → QUESTION (глагол "объясни")
"Я не понимаю" → ANSWER (нет признаков, контекст ответа)
```

### Выбор роли (role-routing, DP.D.044)

До генерации ответа код сопоставляет текст сообщения со списками паттернов (детерминированно, без обращения к модели) и определяет, какая роль отвечает — обычный Консультант или одна из специализированных ролей (Навигатор, Диагност, Наставник). Функция `_detect_role()` в `states/common/consultation.py`.

**WP-498 Ф14 (05.09) — «одно имя наружу».** Пилот и независимая ревью-модель (Fable) нашли: участники не различают Наставника/Навигатора/Диагноста между собой, а по DP.SC.197/DP.ROLE.042 §5-6 Навигатор и Диагност — компоненты связки Наставника, не отдельные роли того же уровня. Автодетект по содержанию текста (без явного имени) теперь **всегда** ведёт к Наставнику — он сам решает внутри диспетчер-промпта (`mentor.md`, сценарии 10-11), нужен ли компонент Навигатора (выбор пути, ритм, мемы) или Диагноста (формальная диагностика ступени). Отдельные имена navigator/diagnostician остаются доступны только тем, кто их осознанно назвал:

1. **Явный префикс.** Сообщение начинается с названия роли — «Навигатор, …», «Диагност, …», «Наставник, …» (или английский аналог) — роль берётся сразу, отвечает соответствующий отдельный промпт (`navigator.md`/`diagnostician.md`/`mentor.md`).
2. **Автодетект по содержанию.** Если префикса нет — сначала проверяются узкие якоря «назови понятие» (сценарий 9, WP-498 Ф11, тоже дают `"mentor"`), затем текст проверяется на вхождение фраз из бывших списков Диагноста и Навигатора (в этом порядке) — но независимо от того, какой список совпал, роль всегда `"mentor"`. Порядок списков внутри кода сохранён только чтобы отсечь ложные срабатывания друг на друге (сужение лексики Ф12/Ф13), не для выбора итоговой роли.

**Пример (обновлён под Ф14):** сообщение «у меня не получается учиться» матчит фразу «не получается учиться» из бывшего списка Навигатора — итоговая роль всё равно `"mentor"`, ответ строится по сценарию 10 `mentor.md` (алгоритм выбора пути/мема), а не по отдельному `navigator.md`.

**Форсированная роль.** `session_ctx['force_role']` держит выбранную роль на первый вопрос сессии (например, при переходе из другого сценария), затем сама сбрасывается. Поддерживает только Навигатора и Диагноста (команды `/navigator`, `/diagnose`) — Наставник через этот механизм не форсируется, но с Ф14 он и не нужен: тот же алгоритм доступен внутри Наставника автодетектом.

**T4 и Гермес (WP-498 Ф15, 05.09, АрхГейт — вариант Д).** У участников уровня T4 обычные сообщения уходят в Гермеса (внешний ИИ-помощник), минуя консультацию бота. Два исключения решаются в `handlers/fallback.py` ДО вызова Гермеса: (1) «?»-вопрос с распознанной ролью (`_is_role_addressed_question`, Ф12/Ф14) и (2) сообщение без «?», в котором детектор Наставника видит интент «назови понятие» (`_is_concept_naming_request` → `is_explicit_concept_naming_request`): такие сообщения идут в консультацию бота, потому что событие `concept_named` (факты мастерства М10/М11/М14 чек-листа участника) умеет писать только Наставник бота — у Гермеса словаря понятий нет. Без «?» и без префикса «Наставник, …» действует только однозначное для IWE подмножество якорей («понятия IWE», «какой гейт мы применили», «назови понятие/гейт»): у разработчика T4 «какой гейт сработал: AND или OR» или «объясни фотосинтез через понятия» — не про IWE и остаются у Гермеса (холодное ревью 05.09). Второе исключение уважает тот же гейт `allow_global: [consultation]` из `transitions.yaml`, что и «?»-вопрос: из стейта, где консультация не разрешена, сообщение по-прежнему уходит в Гермеса. Два ограничения: (а) Наставник бота не видит переписку участника с Гермесом — отвечает по тексту вопроса и цифровому двойнику; (б) при активном aiogram FSM-стейте (например, ввод в настройках) сообщение без «?» перехватит FSM-хендлер раньше, чем оно дойдёт до этой проверки — сквозной пропуск `ConsultationPassthroughMiddleware` работает только для «?»-текста (известный пробел, не расширялся сознательно: правка middleware требует отдельного смоук-теста по правилу 10.37). Решение и порог отката: `DS-my-strategy/inbox/WP-498/DRR-f15-hermes-concept-named.md`.

## 2. Полный поток обработки

### Диаграмма

```
[Ученик/Читатель]                     [Бот]

"Как развить собранность?" ──────────► Intent Detection
                                      ↓
                                      IntentType.QUESTION
                                      ↓
                                      Служебное: Подтверждение
                                      "💭 Думаю над ответом..."
                                      ↓
                                      ЭТАП 1: Анализ (0-20%)
                                      - Извлечение ключевых слов
                                      - Построение динамического контекста
                                      ↓
                                      ЭТАП 2: Поиск (20-60%)
                                      - Query Expansion
                                      - MCP-Guides поиск
                                      - MCP-Knowledge поиск
                                      - Relevance Scoring
                                      - Deduplication
                                      ↓
                                      ЭТАП 3: Генерация (60-95%)
                                      - Claude API с контекстом
                                      ↓
                                      ЭТАП 4: Сохранение (95-100%)
                                      - INSERT INTO qa_history
                                      ↓
                                      Обратная связь: Консультация
                                      "{ответ}"
                                      "📚 _Источники: ..._"
```

## 3. Извлечение ключевых слов

### Функция get_question_keywords()

**Процесс:**
1. Удаление стоп-слов (вопросительные, служебные, частицы)
2. Фильтрация слов > 2 символов
3. Максимум 5 ключевых слов

**Пример:**
```
"Как развить собранность и фокус?"
→ ["развить", "собранность", "фокус"]
```

**Стоп-слова (удаляются):**
- Вопросительные: что, как, почему, зачем, какой...
- Служебные: это, мне, для, при, об, через...
- Частицы: ли, бы, же, ведь, вот...

## 4. Поиск в MCP

### Два MCP сервера

| Сервер | Назначение | Методы |
|--------|-----------|--------|
| **MCP-Guides** | Руководства | `semantic_search`, `get_guide_sections` |
| **MCP-Knowledge** | База знаний | `search` |

### Query Expansion

Расширение запроса через связанные термины:

```python
TERM_RELATIONS = {
    "собранность": ["фокус", "концентрация", "внимание", "целостность"],
    "хаос": ["расфокус", "разбросанность", "флюгер", "внимание"],
    "агентность": ["автономия", "действие", "инициатива", "контроль"],
    "прокрастинация": ["откладывание", "избегание", "завтра", "потом"],
    ...
}
```

**Пример расширения:**
```
Исходный: "собранность"
Расширенные: ["собранность фокус", "собранность концентрация", "собранность внимание"]
```

### Параллельный поиск

```python
# Для каждого expanded query параллельно:
asyncio.gather(
    mcp_guides.semantic_search(query1),
    mcp_guides.semantic_search(query2),
    mcp_knowledge.search(query1),
    mcp_knowledge.search(query2),
    ...
)
```

### Relevance Scoring

| Критерий | Вес |
|----------|-----|
| Совпадение ключевых слов | 40% |
| Совпадение концепций | 30% |
| Связанные термины | 20% |
| Длина текста | 10% |

**Штрафы:**
- Текст < 100 символов: ×0.5
- Текст < 50 символов: пропускается

**Порог:** score ≥ 0.3

### Semantic Deduplication

Удаление дубликатов:
1. Hash сравнение первых 500 символов
2. Jaccard similarity по ключевым фразам (threshold 0.6)

Отвечаешь на вопросы пользователя {name}.
Профессия: {occupation}

## 7. Сохранение в БД

### Таблица qa_history

```sql
CREATE TABLE qa_history (
    id SERIAL PRIMARY KEY,
    chat_id BIGINT,
    mode TEXT,                    -- 'marathon' или 'feed'
    context_topic TEXT,           -- Название темы
    question TEXT,                -- Исходный вопрос
    answer TEXT,                  -- Ответ Claude
    mcp_sources TEXT DEFAULT '[]',-- JSON массив источников
    created_at TIMESTAMP DEFAULT NOW()
)
```

### Пример записи

```python
await save_qa(
    chat_id=123456,
    mode='marathon',
    context_topic='День хаоса',
    question='Как развить собранность?',
    answer='Собранность — это способность...',
    mcp_sources=['Руководство: Фокус', 'База знаний: Внимание']
)
```

| Параметр | Марафон | Лента |

## 10. Обработка ошибок

### Сценарии

| Ситуация | Действие |
|----------|----------|
| MCP не отвечает | Fallback на базовый поиск |
| Низкий score | Фильтрация результатов |
| Claude не отвечает | Сообщение об ошибке |
| Ошибка сохранения | Логирование, ответ отправляется |

### Fallback стратегия

```python
if len(results) < 2:
    # Генерируем упрощённые запросы
    fallback_queries = [
        extract_key_concepts(query),
        simplify_query(query)
    ]
    # Повторный поиск
```
