## 1. Распознавание вопроса

### Префикс `?` — гарантированный триггер

Пользователь может начать сообщение с `?` чтобы **гарантированно** задать вопрос к ИИ:

```
Пользователь → ?Что такое собранность?

Бот → [Консультация через Claude + MCP]
      "Собранность — это..."

      💬 *Ожидаю:* ваш ответ на вопрос (≥20 символов)
```

**Важно:** После ответа на консультацию бот возвращается к ожиданию ответа на урок/задание. Пользователь может сразу продолжить и написать свой ответ — он будет засчитан.

### Поддерживаемые состояния

| FSM-состояние | После консультации |
|---------------|-------------------|
| `waiting_for_answer` | Возвращается к ожиданию ответа на урок |
| `waiting_for_bonus_answer` | Возвращается к ожиданию ответа на бонус |
| `waiting_for_work_product` | Возвращается к ожиданию РП |
| `waiting_fixation` (Лента) | Возвращается к ожиданию фиксации |

### Intent Detection (автоматический)

Если сообщение НЕ начинается с `?`, бот определяет тип через `detect_intent()`:

**Признаки вопроса:**
- Заканчивается на `?`
- Начинается с вопросительного слова (что, как, почему, why, how, qué...)
- Содержит конструкции: "можно ли", "а что если", "объясни", "скажи"

**Вероятностная оценка (score ≥ 0.7):**

| Признак | Баллы |
|---------|-------|
| Вопросительный знак | +0.5 |
| Вопросительное слово в начале | +0.3 |
| Вопросительные слова в тексте | +0.1 |
| Фразы "что такое", "как работает" | +0.3 |
| Длинный текст без признаков | ×0.5 |

**Примеры:**
```
"Как работает собранность?" → QUESTION (score 0.8)
"Объясни концепцию" → QUESTION (глагол "объясни")
"Я не понимаю" → ANSWER (нет признаков, контекст ответа)
```

### Выбор роли (role-routing, DP.D.044)

До генерации ответа код сопоставляет текст сообщения со списками паттернов (детерминированно, без обращения к модели) и определяет, какая роль отвечает — обычный Консультант или одна из специализированных ролей (Навигатор, Диагност, Наставник). Функция `_detect_role()` в `states/common/consultation.py`.

**Два шага, по приоритету:**

1. **Явный префикс.** Сообщение начинается с названия роли — «Навигатор, …», «Диагност, …», «Наставник, …» (или английский аналог) — роль берётся сразу.
2. **Автодетект по содержанию.** Если префикса нет — текст проверяется на вхождение фраз из трёх списков, в фиксированном порядке: **Диагност → Навигатор → Наставник**. Побеждает первое совпадение.

**Почему такой порядок.** Наставник — связка из четырёх ролей (самое широкое полномочие отвечать), поэтому ошибочный роутинг в него дороже, чем в узкую роль. При конфликте лексики более специфичная роль (Диагност/Навигатор) выигрывает.

**Пример конфликта:** сообщение «у меня не получается учиться» содержит фразу «не получается учиться» (паттерн Навигатора) — и одновременно строку «не получается», которая сама по себе входит в список Наставника. Фиксированный порядок проверки (диагност → навигатор → наставник) доходит до Навигатора раньше и отдаёт роль ему, даже не проверяя список Наставника.

**Форсированная роль.** `session_ctx['force_role']` держит выбранную роль на первый вопрос сессии (например, при переходе из другого сценария), затем сама сбрасывается. На эту дату (12.08) поддерживает только Навигатора и Диагноста — Наставник через этот механизм не форсируется.

## 2. Полный поток обработки

### Диаграмма

```
[Ученик/Читатель]                     [Бот]

"Как развить собранность?" ──────────► Intent Detection
                                      ↓
                                      IntentType.QUESTION
                                      ↓
                                      Служебное: Подтверждение
                                      "💭 Думаю над ответом..."
                                      ↓
                                      ЭТАП 1: Анализ (0-20%)
                                      - Извлечение ключевых слов
                                      - Построение динамического контекста
                                      ↓
                                      ЭТАП 2: Поиск (20-60%)
                                      - Query Expansion
                                      - MCP-Guides поиск
                                      - MCP-Knowledge поиск
                                      - Relevance Scoring
                                      - Deduplication
                                      ↓
                                      ЭТАП 3: Генерация (60-95%)
                                      - Claude API с контекстом
                                      ↓
                                      ЭТАП 4: Сохранение (95-100%)
                                      - INSERT INTO qa_history
                                      ↓
                                      Обратная связь: Консультация
                                      "{ответ}"
                                      "📚 _Источники: ..._"
```

## 3. Извлечение ключевых слов

### Функция get_question_keywords()

**Процесс:**
1. Удаление стоп-слов (вопросительные, служебные, частицы)
2. Фильтрация слов > 2 символов
3. Максимум 5 ключевых слов

**Пример:**
```
"Как развить собранность и фокус?"
→ ["развить", "собранность", "фокус"]
```

**Стоп-слова (удаляются):**
- Вопросительные: что, как, почему, зачем, какой...
- Служебные: это, мне, для, при, об, через...
- Частицы: ли, бы, же, ведь, вот...

## 4. Поиск в MCP

### Два MCP сервера

| Сервер | Назначение | Методы |
|--------|-----------|--------|
| **MCP-Guides** | Руководства | `semantic_search`, `get_guide_sections` |
| **MCP-Knowledge** | База знаний | `search` |

### Query Expansion

Расширение запроса через связанные термины:

```python
TERM_RELATIONS = {
    "собранность": ["фокус", "концентрация", "внимание", "целостность"],
    "хаос": ["расфокус", "разбросанность", "флюгер", "внимание"],
    "агентность": ["автономия", "действие", "инициатива", "контроль"],
    "прокрастинация": ["откладывание", "избегание", "завтра", "потом"],
    ...
}
```

**Пример расширения:**
```
Исходный: "собранность"
Расширенные: ["собранность фокус", "собранность концентрация", "собранность внимание"]
```

### Параллельный поиск

```python
# Для каждого expanded query параллельно:
asyncio.gather(
    mcp_guides.semantic_search(query1),
    mcp_guides.semantic_search(query2),
    mcp_knowledge.search(query1),
    mcp_knowledge.search(query2),
    ...
)
```

### Relevance Scoring

| Критерий | Вес |
|----------|-----|
| Совпадение ключевых слов | 40% |
| Совпадение концепций | 30% |
| Связанные термины | 20% |
| Длина текста | 10% |

**Штрафы:**
- Текст < 100 символов: ×0.5
- Текст < 50 символов: пропускается

**Порог:** score ≥ 0.3

### Semantic Deduplication

Удаление дубликатов:
1. Hash сравнение первых 500 символов
2. Jaccard similarity по ключевым фразам (threshold 0.6)

## 7. Сохранение в БД

### Таблица qa_history

```sql
CREATE TABLE qa_history (
    id SERIAL PRIMARY KEY,
    chat_id BIGINT,
    mode TEXT,                    -- 'marathon' или 'feed'
    context_topic TEXT,           -- Название темы
    question TEXT,                -- Исходный вопрос
    answer TEXT,                  -- Ответ Claude
    mcp_sources TEXT DEFAULT '[]',-- JSON массив источников
    created_at TIMESTAMP DEFAULT NOW()
)
```

### Пример записи

```python
await save_qa(
    chat_id=123456,
    mode='marathon',
    context_topic='День хаоса',
    question='Как развить собранность?',
    answer='Собранность — это способность...',
    mcp_sources=['Руководство: Фокус', 'База знаний: Внимание']
)
```

## 10. Обработка ошибок

### Сценарии

| Ситуация | Действие |
|----------|----------|
| MCP не отвечает | Fallback на базовый поиск |
| Низкий score | Фильтрация результатов |
| Claude не отвечает | Сообщение об ошибке |
| Ошибка сохранения | Логирование, ответ отправляется |

### Fallback стратегия

```python
if len(results) < 2:
    # Генерируем упрощённые запросы
    fallback_queries = [
        extract_key_concepts(query),
        simplify_query(query)
    ]
    # Повторный поиск
```

## 12. Постоянная сессия и память диалога (РП-498 Ф17)

После ответа бот остаётся в консультации (персистентная сессия): следующий текст без `?` считается продолжением диалога, и модель получает историю.

| Параметр | Значение |
|----------|----------|
| Где хранится | `development.user_state.current_context`, ключ `consultation_history` |
| Размер | до 5 последних пар (вопрос, ответ). Последняя пара хранится почти целиком (вопрос 2500 + 500, ответ 3000 + 1000 символов: голова и хвост), чтобы встречное предложение в конце ответа не терялось; когда приходит новая пара, предыдущая сжимается до 450 (вопрос) и 600 (ответ) символов. Пропуск в середине помечается `[…пропущено N символов…]`, рез идёт по границе слова. Потолок: около 11,4 тысячи символов на пять пар (измерено) |
| Что хранится | ответ без подписи роли и без блока «Источники»: читателю они нужны, модели в хвосте ответа нужна последняя фраза |
| Окно неактивности | 15 минут (`SESSION_TIMEOUT_SEC`, равно `SM_EXPECTING_REPLY_STATES["common.consultation"]` в минутах), отсчёт от последнего ответа, нажатия «✏️ Обратная связь» или сохранённого замечания. После паузы новый вопрос начинает сессию заново; роль из `/navigator` при этом сохраняется |
| Что стирает историю | выход из консультации (команда, меню), кнопка «↩️ Завершить», вход в новую роль, таймаут |
| Что историю НЕ стирает | кнопки «🔍 Подробнее» и «✏️ Обратная связь» под ответом: они делают переход в то же состояние, и `exit()` при этом не вызывается (`keeps_session_on_reentry`, `states/base.py`). любой новый вопрос (в том числе «Подробнее») отменяет ожидание замечания; ответ, уже стоящий последним в истории (совпадают начало и конец), повторно в запрос не цитируется |
| Короткие реплики | пока диалог жив (история не пуста, окно не истекло), любая реплика, где есть буква или цифра («да», «ок», «2», «опиши»), продолжает его: так читатель отвечает на предложение в конце ответа бота. Реплика из одних знаков и эмодзи («.», «👍», одинокий `?`) получает подсказку; в пустой сессии подсказку получает и текст короче 3 символов |
| Поиск знаний для короткой реплики | реплика короче 25 символов («да», «опиши») ищется в базе знаний вместе с последним содержательным вопросом диалога (до 300 символов), а не сама по себе: поиск по слову «да» ничего не находит, и модель отвечала бы без фактов о теме. Длинная реплика и реплика без истории ищутся как есть |
| Кнопка «🔍 Подробнее» | просьба углубить ответ, а не оценка «не помог»: `qa_history.helpful` не ставится, разбор «не помог» не запускается, пишется событие `qa_refine` (`qa_id`, `refinement_round`). 👍 по-прежнему ставит `helpful=true`, «✏️ Обратная связь» сохраняет замечание и запускает разбор |
| Откуда входят | команда с `?`, `/navigator`, кнопки под ответом, свободный текст в Ленте (`FEED_QUESTIONS_VIA_CONSULTATION`, см. `scenario-01-02-feed.md`); из Ленты в `context_topic` приходят темы недели, сессия помнит их до конца (реплики после первого ответа знают тему) |
| Диагностика в логе | `[Consultation] session cleared: reason=exit\|timeout\|end_session\|role_entry pairs=N`; строка `enter` содержит `history_pairs` и `history_chars`; строка `Consultation: multi-turn\|new with N messages` пишется для каждого ответа |
