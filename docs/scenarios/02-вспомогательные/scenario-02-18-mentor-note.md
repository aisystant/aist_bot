# 02.18 `/mentor_note` — сохранить заметку о участнике

> Наставник отвечает этой командой на сообщение участника в группе потока —
> бот предлагает подтвердить, что в тексте нет чужих личных данных без
> согласия (карантин), и после подтверждения записывает заметку через
> mentorship-service (`add_participant_note`). Бот сам в базу наставничества
> не пишет — принцип «бот = тонкий клиент» (MEMORY.md). Два экрана подряд
> (запрос подтверждения → результат) — вид B, не микро.

---

## Обзор

| Параметр | Значение |
|----------|----------|
| Команда | `/mentor_note [текст]`, только в группе/супергруппе, ответом на сообщение участника |
| Тип | Вспомогательный (B) — команда → подтверждение кнопкой → результат |
| Файлы | [`handlers/mentorship.py`](../../../handlers/mentorship.py), [`clients/mentorship_service.py`](../../../clients/mentorship_service.py) |
| Доступ | Только читатель потока (`stream_reader.role IN ('mentor','pilot')`) этой группы |
| Внешний сервис | mentorship-service (Railway, `MENTORSHIP_SERVICE_URL`/`MENTORSHIP_SERVICE_TOKEN`) |

---

## 1. Поток

```
Наставник (в группе потока, ответом на сообщение участника):
  /mentor_note                       — тело заметки = текст сообщения-цели
  /mentor_note <свой текст>          — тело заметки = аргумент команды

Бот → «Сохранить как заметку об участнике <имя>? «<текст>»
       ⚠️ Подтверди, что в тексте нет чужих личных данных без согласия.»
       [✅ Да, сохранить] [Отмена]

Наставник нажимает кнопку → бот вызывает add_participant_note сервиса
(quarantineConfirmed=true) → результат тем же сообщением (edit_text).
```

### Кто получает ответ (Ф9)

Бот сначала проверяет, кто вызвал команду. **Посторонний — бот молчит совсем** (ни в группе, ни в
личке): нет привязанного аккаунта платформы, аккаунт не читает ни одного потока, модуль
наставничества отключён. **Ошибки использования уходят наставнику в личку**; в группу приходит
только запрос подтверждения (см. известные ограничения про приватность текста).

### Ответы бота

Ошибки использования команды — **в личку наставнику** (в группу ничего):

- Нет reply-цели: «Ответь этой командой на сообщение участника, которое нужно сохранить как заметку.»
- Заметка о себе (reply на своё же сообщение): «Нельзя сохранить собственное сообщение наставника как заметку об участнике.»
- В сообщении-цели и в аргументе нет текста: «В сообщении-цели нет текста — нечего сохранять.»
- Группа не зарегистрирована за потоком: «Эта группа не зарегистрирована за потоком — сначала /mentor_stream.»
- Вызывающий читает другой поток, не этой группы: «Ты не числишься наставником или пилотом потока S1-2026.3-T.»
- У участника нет аккаунта платформы: «У участника нет привязанного аккаунта платформы — заметку сохранить нельзя.»

Запрос подтверждения и всё после нажатия кнопки — **в группе** (правит то же сообщение или показывает alert; Ф9 этот
блок не менял, вопрос его приватности открыт, см. известные ограничения):

- Отмена (кнопка «Отмена»): «Отменено — заметка не сохранена.»
- Просроченное/уже обработанное подтверждение (нажатие спустя >15 минут или повторное нажатие): «Заметка устарела или уже обработана — повтори /mentor_note.» (alert)
- Успех: «✅ Заметка об участнике <имя> сохранена.»
- Сервис ответил ошибкой уровня приложения (`access_denied`/`invalid_params`): «Не удалось сохранить заметку: <сообщение сервиса>.»
- Сервис недоступен (сеть/не настроен): «Сервис заметок сейчас недоступен — попробуй позже.»

## 2. Известные ограничения

- Ожидающее подтверждение хранится в памяти процесса (`(chat_id, mentor_telegram_user_id) → заметка`), не переживает рестарт/redeploy бота на Railway — то же осознанное узкое сужение, что `_topic_creator_is_mentor_cache` в `engines/mentorship/archive_tap.py`: потеря означает «наставник подтверждает ещё раз» (просто повторить `/mentor_note`), не порчу данных.
- Один незавершённый `/mentor_note` на наставника в чате — новый вызов молча заменяет предыдущий неподтверждённый.
- TTL подтверждения — 15 минут.
- Best-effort детектор совпадения ФИО/username/email других участников потока в тексте — не реализован (решение пир-сессии с Kimi 17.09, открытый пункт WP-578).
- **Приватность текста заметки в группе — открыто (вне Ф9).** Запрос подтверждения повторяет текст заметки в группу, а при форме `/mentor_note <свой текст>` сама команда наставника уже публична. Перенос ответа бота в личку сообщение-команду не скроет. Нужен отдельный контур (запрет аргумента в группе, ввод только в личке, либо удаление команды ботом при достаточных правах) — решение пилота 21.09: отдельным шагом после Ф9.
- Наставник без привязанного к боту аккаунта получает тишину, как посторонний; личка с ботом должна быть открыта заранее, иначе ошибка использования не дойдёт (в журнале предупреждение, публичного резервного сигнала нет — решение пилота 21.09).
