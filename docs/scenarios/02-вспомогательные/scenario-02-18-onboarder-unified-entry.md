# 02.18 Сценарий единого входа в Онбордера (offer.py)

> **WP-406 Ф5.** Описывает, когда и как появляется кнопка «🎓 Освоиться» и как она
> ведёт в Х2/Х3. Архитектура гейта: `core/onboarder/offer.py`.

---

## Обзор

| Параметр | Значение |
|----------|----------|
| Кнопка | «🎓 Освоиться» (`callback_data=onboarder_start`) |
| Где появляется | Экран B после `/start`; приветствие вернувшегося; ответ Гермеса на онбординг-вопросы (только тир < T3) |
| Гейт | `should_offer(chat_id)`: открытый разрыв Х2/Х3 **И** не на cooldown |
| Cooldown | 3 дня с последнего показа (`_COOLDOWN_DAYS = 3`) |
| Единый источник текста | `offer_payload()` — возвращает `text`, `button_text`, `callback_data`; handlers оборачивают в `InlineKeyboardMarkup` |

---

## 1. Условие показа — should_offer

Два условия одновременно:

1. **Открытый разрыв:** `not (status["x2_done"] and status["x3_done"])` — хотя бы одна из отметок `x2_completed_at` / `x3_completed_at` отсутствует.
2. **Не на cooldown:** `offer_shown_at` в `onboarding_context` либо отсутствует, либо старше 3 дней.

`should_offer` — чистый read-path без side effects. Если нужно зафиксировать факт показа — вызвать `mark_offered(chat_id)` отдельно после фактической отправки.

> **Почему cooldown важен:** у существующих пользователей разрыв Х2/Х3 был открыт изначально (NULL-значения в БД). Без cooldown кнопка появлялась на каждом `/start`. 3 дня — компромисс между навязчивостью и ненадоедливостью.

---

## 2. Точки показа кнопки

### 2.1 Экран B — быстрый путь `/start`

`handlers/onboarding.py:_show_screen_b` вызывает `should_offer` → если True, добавляет кнопку «🎓 Освоиться» к набору кнопок Экрана B.

Экран B показывается новым пользователям и пользователям без активного марафона. Ядро быстрого пути (`/start`): `handlers/onboarding.py:cmd_start`.

### 2.2 Приветствие вернувшегося

При `/start` пользователя с активным марафоном — если `should_offer` вернул True, кнопка добавляется в приветственное сообщение. Пользователь не прерывается марафон, но видит оффер.

### 2.3 Гермес — онбординг-вопросы

`handlers/hermes.py` для пользователей ниже T3: если вопрос классифицирован как онбординг-релевантный (по ключевым словам), в конце ответа добавляется кнопка «🎓 Освоиться». Произвольный вопрос кнопку **не** вызывает — только явно связанные с «как начать», «как устроен бот», «куда обращаться».

---

## 3. Нажатие — on_onboarder_start

`callback_data=onboarder_start` → `handlers/onboarding.py:on_onboarder_start`:
1. Вызывает `core.onboarder.handle(intern, message)`.
2. `handle()` читает статус → выбирает первый открытый разрыв: Х2 (если не закрыт) раньше Х3.
3. Запускает `run_x2()` или `run_x3()`.

---

## 4. Единый источник текста — offer_payload()

```python
offer_payload() → {
    "text": "Хочешь освоиться в сообществе? ...",
    "button_text": "🎓 Освоиться",
    "callback_data": "onboarder_start",
}
```

Все три точки показа (Экран B, вернувшийся, Гермес) получают текст и кнопку из одного `offer_payload()`. Изменить текст — только в `offer.py:_OFFER_TEXT / _BUTTON_TEXT`.

## 6. Инварианты

- Текст кнопки и callback_data не разбросаны по хендлерам — единственный источник `offer_payload()`.
- `mark_offered` вызывается **после** фактической отправки сообщения, не до.
- `should_offer` не меняет стейт — только читает.
- Гермес показывает кнопку только при онбординг-релевантных вопросах (не спамит при любом вопросе).
