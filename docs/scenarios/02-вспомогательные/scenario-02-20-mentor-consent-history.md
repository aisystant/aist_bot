# 02.20 `/mentor_consent_history` — согласие на перенос уже написанного раньше

> Отдельное от `/mentor_consent` (02.17) согласие: то смотрит в будущее (что
> собирать дальше), это — в прошлое (что участник уже написал в общем чате
> потока и в личке до появления архива). Одной кнопкой их объединять нельзя:
> комментарий к схеме согласий прямо запрещает трактовать согласие как
> задним числом покрывающее уже собранные данные (`neon-migrations/mvp/229-
> wp316-consent-grant.sql:29`, «Retroactive expansion запрещена»). Решение
> пир-сессии 23.09 (Claude+Kimi+Codex, WP-578 Ф11) — простой вариант без
> предпросмотра объёма переписки (дешевле, но участник не видит, сколько
> именно перенесётся).

---

## 1. Обзор

| Параметр | Значение |
|----------|----------|
| Команда | `/mentor_consent_history`, только в личке (private) |
| Вид | Вспомогательная (B) — команда → две инлайн-кнопки → подтверждение, без FSM |
| Файлы | [`handlers/mentorship.py`](../../../handlers/mentorship.py) (`cmd_mentor_consent_history`, `cb_mentor_consent_history`), [`db/queries/consent.py`](../../../db/queries/consent.py) (переиспользован `set_consent_grant`, не новый writer) |
| БД | Neon `learning.consent_grant` — новая scope-строка `mentor_archive_history`, тот же принцип, что у `mentor_archive_dm`/`mentor_archive_group` (обычное текстовое значение, `scope TEXT` без `CHECK`/enum — новая DDL-миграция не нужна) |
| Важно | Не расширяет `_CONSENT_SCOPES`/`/mentor_consent` — сознательно отдельная команда, отдельный callback-namespace (`mentor_consent_history:accept`/`:revoke`), чтобы не смешать согласие на будущее и на прошлое в одном клике |

## 2. Flow

```
1. Участник (в личке с ботом): /mentor_consent_history
2. Бот показывает текст + две кнопки: [✅ Да, согласен] [Отозвать]
3. Нажатие «Да» → set_consent_grant(account_id, "mentor_archive_history", True)
4. Подтверждение: «✅ Согласие на перенос прошлой переписки зафиксировано.»
   ИЛИ нажатие «Отозвать» → granted=False → «Согласие отозвано.»
```

## 3. Сообщение бота (текст согласия)

```
Наставник хочет перенести в архив и уже написанное вами раньше в общей
группе потока и в личных сообщениях боту (не только новые сообщения —
это отдельное решение). Согласны?

[✅ Да, согласен]  [Отозвать]
```

## 4. Кто запускает и когда

Наставник/пилот лично просит каждого участника выполнить команду перед
запуском переноса истории (`mentorship-service/scripts/telegram-history/
README.md`, шаг 5, `sink-cli.ts`). Импорт читает `consent_grant` по этому
scope на момент запуска — участник без записи согласия получит только
метаданные (кто кому писал, когда), без текста, тем же путём, что и для
`mentor_archive_dm`/`mentor_archive_group` при живом сборе.

**Известное ограничение (не забытый случай):** нет deep-link или кнопки
рассылки всем участникам потока сразу — каждый вызывает команду сам, тем же
способом, что и `/mentor_consent`. Автоматизация массовой рассылки — не в
объёме этого прохода.

## 5. Отзыв согласия задним числом

Как и у `/mentor_consent` (02.17) — отзыв гасит запись новых импортов, но
не удаляет уже перенесённый текст. Удаление по запросу участника —
отдельный контракт (РП-554, right-to-be-forgotten).
