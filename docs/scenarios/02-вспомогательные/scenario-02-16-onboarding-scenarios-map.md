# Сценарий 02-16 v2: Карта сценариев онбординга — две оси

> **SC:** DP.SC.168 (Онбординг), DP.SC.151 (OnboardingMarkers), DP.SC.155 (Setup Journey)
> **WP:** WP-349 Ф31
> **Вид:** B (вспомогательный — многошаговый поток)
> **Версия:** 2 (2026-06-05) — переписано под две оси онбординга

---

## Назначение

Документ описывает все точки входа пользователя в платформу через **любой MCP-клиент** (бот, claude.ai, ChatGPT, Cursor, VS Code).

Каждый поток соответствует **координате (тир, ступень/квалификация)** — не каналу. Канал иллюстративный, один из возможных.

---

## Принцип: интерфейс ≠ тир

Канал (бот / claude.ai / Кими / GPT / VS Code) **не определяет** тир. В боте может быть пользователь T2-T4; из claude.ai/Кими/GPT можно подключить **только Aisystant MCP**, движок — **своя подписка LLM клиента**, и затем подключить всё нужное (подписку БР, ЦД, GitHub) → **достичь T4 из любого MCP-клиента**.

## Сценарий 0 — T0-граница (новый)

> **Координата:** (T0, —) — подключил MCP, не вошёл в Ory.
> **Канал:** любой MCP-клиент.

**Поток:**
```
1. Пользователь подключает Aisystant MCP
2. Агент канала дёргает get_journey_state → (T0, —)
3. get_next_onboarding_step → «Приветствие T0» (Сообщение 0 v4)
   - Доступно: knowledge_search, get_instructions, get_onboarding_context
   - Приглашение: grant_consent + регистрация Ory
4. Пользователь либо входит (→ T1, Сценарий 1), либо остаётся на T0
```

**Режим отказа:** нет Ory → показываем знания + приглашение войти. Не агрегируем, не нудим.

## Сценарий 1 — «Хочу понять платформу и оснаститься»

> **Координата:** (T1, —) — вошёл, consent дан.
> **Канал:** любой (пример: бот).

**Поток:**
```
1. get_journey_state → (T1, —)
2. get_next_onboarding_step → «Первый шаг после входа» (Сообщение 1 v4)
   - Предлагает диагностику (содержательная ось)
3. [Узнать ступень] → /diagnose → Сценарий 2
4. [Обзор платформы] → /setup:

   🗺 Ваш путь оснащения
   ✅ Аккаунт подключён (T1)
   ⬜ Диагностика — не пройдена        [Узнать ступень →]
   ⬜ Программа — не выбрана
   ⬜ Подписка — нет
   ⬜ Персональное руководство — нет
   ⬜ Своя среда — не подключена

5. [Следующий шаг] → guided flow:
   шаг 1: Диагностика → /diagnose-iwe
   шаг 2а: Универсальное руководство (ступень 1) → /learn
   шаг 2б: Универсальное руководство (ступень 2+) → /learn stream=N
   шаг 3: Подписка T2 → ссылка оплаты (когда нужна персонализация)
   шаг 4: Заполнить ЦД → /twin (T3)
   шаг 5: Подключить GitHub → github_connect (T4)
```

**Re-entry:** если `last_active_date < today` → «Продолжим с [шаг]?»

## Сценарий 2 — «Хочу понять свой уровень»

> **Координата:** (T1, —) → (T1, N).
> **Канал:** любой.

**Поток:**
```
1. get_journey_state → (T1, —)
2. get_next_onboarding_step → «Пройди диагностику» (Соорбщение 1 v4)
3. [Узнать ступень] → cmd_diagnose() (с FSMContext в боте, или диалог в браузере)
4. Диалог диагностики (≤5 вопросов, CAT-принцип)
5. Результат: ступень + bottleneck + рекомендованная программа
6. get_journey_state → (T1, N)
7. get_next_onboarding_step → «Результат диагностики» (Сообщение 2 v4)
```

**Результат:** `learning.cp_assessments` — новая запись.

## Сценарий 3 — «Хочу начать марафон прямо сейчас»

> **Координата:** (T1, 1) — ступень 1 (Случайный).
> **Канал:** любой.

**Поток:**
```
1. get_journey_state → (T1, 1)
2. get_next_onboarding_step → «Начни универсальное руководство» (Сообщение 2 v4)
3. [Начать марафон] → start_marathon_flow()
```

**Deep-link (уже онбордированный):**
```
/start marathon → onboarding.py: args[1]=="marathon" AND onboarding_completed
→ start_marathon_flow() напрямую (пропуск consent и intent-экрана)
```

## Сценарий 4 — «Хочу освоить всю платформу поэтапно»

> **Координата:** (T1→T4, —) — полный путь оснащения.
> **Канал:** любой.

**Поток:**
```
consent → get_journey_state → (T1, —)
→ get_next_onboarding_step → Сообщение 1 v4
→ /diagnose → (T1, N) → Сообщение 2 v4
→ /learn → (T1, N, программа) → Сообщение 3 v4
→ /slot ритм → эвристика: подписка? → Сообщение 5 v4 (T2)
→ /twin → (T3) → Сообщение 6 v4
→ github_connect → (T4) → Сообщение 7 v4
```

## Сценарий 5 — «Пришёл по приглашению знакомого»

> **Координата:** (T0→T1, —).
> **Канал:** бот (deep-link).

**Поток:**
```
1. /start ref_<uuid>
2. generic welcome: «Привет! Тебя пригласил друг из сообщества Aisystant."
3. referral_uuid сохраняется в current_context
4. Обычный онбординг (регистрация аккаунта) → T1
5. consent_accept: write_referral_source(account_id, referral_uuid) в Neon
6. intent-экран (те же кнопки: Марафон / Ступень / Обзор)
```

**PII:** имя рефери НЕ показывается (GDPR). Generic «друг из сообщества».

## Сценарий 6 — «Вернулся после паузы»

> **Координата:** (any, N) — любой тир, ступень известна.
> **Канал:** любой.

**Поток:**
```
1. /start → mode_select.enter() → days_inactive ≥ 7
2. get_journey_state → (тир, ступень)
3. get_next_onboarding_step → «Возврат после паузы» (Сообщение 9 v4)
4. 3 кнопки намерений:
   [Вернуться к руководству] [Записать время] [Обновить ступень]
```

## Сценарий 7 — «Оплатил, но не прошёл диагностику» (новый)

> **Координата:** (T2+, —) — оплативший без диагностики.
> **Канал:** любой.
> **Особый случай:** единственный, где тир бежит вперёд содержания.

**Поток:**
```
1. get_journey_state → (T2+, —)
2. get_next_onboarding_step → «Демо-L0» (Сообщение 4 v4)
   - Эвристика: tier≥T2 AND ступень неизвестна → демо-L0 первым
   - Немедленная ценность: «вот что платформа уже видит"
   - Диагностика — улучшение, не шлагбаум
3. [Пройти диагностику] → /diagnose → (T2, N) → Сообщение 5 v4
4. [Продолжить с демо] → /learn → универсальное руководство
```

## Сценарий 8 — «Пишу текстом что хочу»

> **Координата:** (any, N).
> **Канал:** бот (свободный текст).

**Поток:**
```
1. Пользователь пишет текст в боте
2. fallback.py:on_unknown_message:
   а. intern = get_intern(chat_id)
   б. intern.onboarding_completed AND sm_state is None → Ф22 check
3. detect_onboarding_intent(text) → match по ONBOARDING_INTENT_MAP
4. route_onboarding_intent() → вызов того же handler что и кнопка
```

**ONBOARDING_INTENT_MAP** (word-boundary match, нижний регистр):
| Интент | Ключевые фразы |
|--------|----------------|
| marathon | «начать марафон», «запустить марафон», «хочу учиться", «начать учёбу" |
| diagnose | «узнать ступень», «моя ступень", «мой уровень", «диагностика" |
| setup | «обзор платформы», «как работает платформа", «оснащение" |

## Переходы между тирами (маркеры B–G v2)

Контролёр OnboardingMarkers проверяет состояние и отправляет CTA через `get_next_onboarding_step`:

| Маркер | Координата | Условие | Сообщение v4 | CTA |
|--------|------------|---------|--------------|-----|
| B-low | (T1, 1) | Диагностика пройдена, ступень 1, нет подписки | Сообщение 2 | Универсальное руководство |
| B-high | (T1, 2+) | Диагностика пройдена, ступень 2+, нет подписки | Сообщение 2 | Универсальное руководство / подписка |
| C | (T1, N) | Активен 7 дней, нет подписки | Сообщение 3 | Продолжить ритм |
| D/E | (any, N→N+1) | Ступень выросла | Сообщение 8 | Проверка системы |
| F | (T2, N) | Подписка + ЦД заполнен | Сообщение 6 | Managed-репо |
| G | (T3, N) | Managed-репо + активен 14+ дней | Сообщение 7 | Свой GitHub (T4) |
| H | (T2+, —) | Оплатил без диагностики | Сообщение 4 | Демо-L0 + диагностика |

## Эвристика приоритета `get_next_onboarding_step` (v2)

```
IF ступень неизвестна:
  → СОДЕРЖАНИЕ: диагностика (5 мин, free)
  → канал: любой MCP-клиент

ELIF тир ≥ T2 AND ступень неизвестна:
  → демо-L0 первым (немедленная ценность)
  → диагностика — улучшение, не шлагбаум

ELIF тир < мин-тир-программы:
  → ОСНАЩЕНИЕ: подключи X под программу Y
  → НЕ «вообще к T4", а под конкретную программу

ELSE:
  → СОДЕРЖАНИЕ: следующий шаг программы

второй шаг — опционально («также доступно»)
«Оснащение вперёд» — только по явному запросу (request_equipment_upgrade)
```

## Cooldown-политика

- Все нуджи: 24h cooldown (`last_nudge_at`)
- CTA-клик → немедленно обновляет `last_nudge_at`
- Повторный тик в тот же день → видит cooldown → не присылает дубль
