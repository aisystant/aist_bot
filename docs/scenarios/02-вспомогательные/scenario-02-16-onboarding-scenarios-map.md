# Сценарий 02-16: Карта сценариев онбординга — разные интересы пилота

> **SC:** DP.SC.151 (OnboardingMarkers), DP.SC.155 (Setup Journey), DP.SC.157 (Марафон)
> **WP:** WP-349 OnboardingMarkers v2
> **Вид:** B (вспомогательный — многошаговый поток)
> **Реализовано:** 2026-05-23

## Назначение

Документ описывает все точки входа пользователя в платформу через бота и соответствующие им потоки.
Каждый поток соответствует определённому **интересу** (намерению) пользователя в момент первого знакомства.

## Сценарий 1 — «Хочу понять платформу и оснаститься»

**Интерес:** пилот хочет методично пройти путь T1→T4, понять каждый шаг.

**Точки входа:**
- Кнопка «Обзор платформы» в intent-экране после consent
- Команда `/setup`

**Поток:**
```
1. /start → onboarding (регистрация аккаунта Aisystant)
2. → consent (согласие на трекинг ступени)
3. → intent-экран: [Начать марафон] [Узнать ступень] [Обзор платформы]
4. → [Обзор платформы] → /setup: дашборд пути

   🗺 Ваш путь оснащения
   ✅ Аккаунт подключён (T1)
   ⬜ Диагностика — не пройдена        [Узнать ступень →]
   ⬜ Начать поток — ?
   ⬜ Подписка — нет
   ⬜ Браузерная среда — не подключена
   ⬜ База знаний — не создана

5. → [Следующий шаг] → guided flow:
   шаг 1: Диагностика → /diagnose-iwe
   шаг 2а: Марафон (ступень 1) → /learn
   шаг 2б: Поток S{N} (ступень 2+) → /learn stream=N
   шаг 3: Подписка T2 → ссылка оплаты
   шаг 4: Браузерная среда → /connect
   шаг 5: База знаний → /personal-guide-start
```

**Re-entry:** если `last_active_date < today` → вместо полного дашборда показывается «Продолжим с [шаг]?».

**Источники данных (свежие, не кэш):**
- Диагностика: `learning.cp_assessments` напрямую
- Подписка: `tier_detector.detect_ui_tier()` (5-мин кэш)
- Браузер/База знаний: `onboarding_state.first_use_*`

## Сценарий 2 — «Хочу понять свой уровень»

**Интерес:** пилот хочет диагностику — куда ему идти учиться.

**Точки входа:**
- Кнопка «Узнать ступень» в intent-экране
- Свободный текст «ступень», «диагностика», «мой уровень» (Ф22)

**Поток:**
```
1. /start → onboarding → consent → intent-экран
2. → [Узнать ступень] → cmd_diagnose() напрямую (с FSMContext)
3. → диалог диагностики (≤5 вопросов, CAT-принцип)
4. → результат: ступень + bottleneck + рекомендованный поток S{N}
```

**Результат:** `learning.cp_assessments` — новая запись с cp-профилем.

## Сценарий 3 — «Хочу начать марафон прямо сейчас»

**Интерес:** пилот уже знает о марафоне, хочет быстро приступить.

**Точки входа:**
- Кнопка «Начать марафон» в intent-экране
- Свободный текст «марафон» (Ф22)
- Deep-link `/start marathon` (из Telegram-поста, email, внешней ссылки)

**Поток через intent-экран:**
```
1. /start → onboarding → consent → intent-экран
2. → [Начать марафон] → start_marathon_flow() напрямую
```

**Поток через deep-link (уже онбордированный):**
```
/start marathon → onboarding.py: args[1]=="marathon" AND onboarding_completed
→ start_marathon_flow() напрямую (пропуск consent и intent-экрана)
```

## Сценарий 4 — «Хочу освоить всю платформу поэтапно» [R2]

**Интерес:** пилот хочет последовательный гид по всей платформе (10+ сообщений).

**Статус:** ⏸ заблокирован WP-343 R2 (сообщения 0-10, июнь 2026).

**Планируемый поток:**
```
consent → intent «Обзор платформы» → /setup → WP-343 сообщения 0-10
```

## Сценарий 5 — «Пришёл по приглашению знакомого»

**Интерес:** пилот «подогрет» — знает о платформе от реального пользователя.

**Точки входа:**
- Deep-link `/start ref_<ory_uuid>` (из реферальной ссылки действующего пилота)

**Поток:**
```
1. /start ref_<uuid>
2. → generic welcome: «Привет! Тебя пригласил друг из сообщества Aisystant.»
3. → referral_uuid сохраняется в current_context (Railway DB)
4. → обычный онбординг (регистрация аккаунта)
5. → consent_accept: write_referral_source(account_id, referral_uuid) в Neon
6. → intent-экран (те же кнопки: Марафон / Ступень / Обзор)
```

**PII-решение:** имя рефери НЕ показывается (GDPR). Только generic «друг из сообщества».

**Graceful fallback:** невалидный UUID → generic onboarding без welcome-экрана.

## Сценарий 6 — «Вернулся после паузы»

**Интерес:** пилот T1/T2, не заходил 7+ дней — нужна точка продолжения.

**Точки входа:**
- `/start` или любая команда → mode_select.enter()

**Поток:**
```
1. /start → mode_select.enter() → days_inactive ≥ 7
2. → re-entry экран: «Давно не виделись! Продолжим?»
3. → 3 кнопки намерений:
   [Начать марафон] [Узнать ступень] [Обзор платформы]
4. → соответствующий сценарий (1, 2 или 3)
```

**Условие:** `days_inactive = (moscow_today() - last_active_date).days ≥ 7`

## Сценарий 7 — «Пишу текстом что хочу» (Ф22)

**Интерес:** пилот не нашёл нужную команду, пишет свободным текстом.

**Точки входа:**
- Любой текст без `/` от онбордированного пользователя без активного SM-стейта

**Поток:**
```
1. Пользователь пишет текст в боте
2. → fallback.py:on_unknown_message:
   а. intern = get_intern(chat_id)
   б. intern.onboarding_completed AND sm_state is None → Ф22 check
3. → detect_onboarding_intent(text) → match по ONBOARDING_INTENT_MAP
4. → route_onboarding_intent() → вызов того же handler что и кнопка
```

**ONBOARDING_INTENT_MAP:**
| Интент | Ключевые слова |
|--------|----------------|
| marathon | «марафон», «учиться», «первый урок», «начать обучение» |
| diagnose | «ступень», «уровень», «диагностика», «куда учиться», «какой поток» |
| setup | «настройка», «оснащение», «как работает», «обзор платформы» |

**Fallback:** если текст не матчится → обычный SM-роутинг (показывает меню или mode_select).

**Примечание:** TODO negative-pattern filter (напр. «не хочу марафон» → без intent).

## Переходы между тирами (маркеры B–G)

Контролёр OnboardingMarkers (iwe-server) периодически проверяет состояние каждого пилота и отправляет CTA-нуджи при выполнении условий:

| Маркер | Условие | Сообщение | CTA |
|--------|---------|-----------|-----|
| B-low | Диагностика пройдена, ступень 1, нет подписки | «Готов к T2?» | Подписка |
| B-high | Диагностика пройдена, ступень 2+, нет подписки | «Ступень выросла — открой T2» | Подписка |
| C | Активен 7 дней, нет подписки | «7 дней — самое время» | Подписка |
| D/E | Ступень выросла (engagement_analyzer) | «Рекомендую S{N}» | /learn stream=N |
| F | T2+, активен 14+ дней, нет тайного гита | «Создай личную базу знаний» | /personal-guide-start |
| G | T2+, активен 30+ дней, нет явного гита | «Подключи VS Code» | /connect |

## Cooldown-политика

- Все нуджи: 24h cooldown (`last_nudge_at`)
- CTA-клик → немедленно обновляет `last_nudge_at` (Kimi критика #1, dual-cooldown fix)
- Повторный тик контролёра в тот же день → видит cooldown → не присылает дубль
