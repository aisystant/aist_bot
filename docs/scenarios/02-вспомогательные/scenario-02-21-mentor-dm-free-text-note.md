# 02.21 Голый текст в личке боту — предложить сохранить как заметку

> Наставник пишет боту в личку обычный текст — без команды, без пересылки —
> ожидая, что это попадёт в архив участника, о котором он только что писал
> ([02.19](scenario-02-19-mentor-note-dm.md)). Раньше такой текст молча уходил
> в общий fallback без ответа: живой дефект найден 28.09, когда наставник
> дважды написал длинный текст боту в личку и не получил ни сохранения, ни
> подсказки, ни отказа. Этот сценарий закрывает разрыв, не меняя ни правило
> архивации группы ([process-19](../processes/process-19-mentorship-archive-tap.md)),
> ни способ, которым выставляется «активный участник» (по-прежнему только
> forward+`/mentor_note`/`/mentor_card`, [02.19](scenario-02-19-mentor-note-dm.md) §2).

| Внешний сервис | mentorship-service — тот же вызов `add_participant_note`, что у 02.18/02.19, без изменений |

## 1. Поток

```
Наставник (личка с ботом), недавно (≤2ч) переслал сообщение участника
и ответил /mentor_note или /mentor_card — «активный участник» установлен:

  пишет любой текст боту, без команды, без новой пересылки

Бот:
  1) есть свежий активный участник? нет → пропустить сообщение целиком
     (SkipHandler — дальше работает обычная маршрутизация бота, как раньше)
  2) есть → «Сохранить это как заметку об участнике <имя>? «<текст>»
            ⚠️ Подтверди, что в тексте нет чужих личных данных без согласия.»
            [✅ Да, сохранить] [Отмена]
Наставник нажимает кнопку → тот же add_participant_note, что у 02.18/02.19.
```

**Нет активного участника** (наставник ничего не пересылал в последние 2 часа, или он не наставник вообще) — сообщение НЕ перехватывается: бот ведёт себя точно так же, как до этой правки. Никакой подсказки не показывается — молчаливый fallback для этого случая осознанно оставлен как есть (пилот подтвердил минимальный вариант, не вводить обработку голого forward отдельно, эскалация той же сессии).

## 2. Почему это безопасно для обычных участников и личного использования бота самим наставником

- «Активный участник» — тот же in-memory словарь, что у [02.19](scenario-02-19-mentor-note-dm.md), ключ — telegram id наставника. Для всех, кто ни разу не проходил через forward+`/mentor_note`/`/mentor_card`, словарь пуст — хендлер завершается на первой же проверке без единого сетевого вызова (`resolve_ory_id_from_chat` не вызывается).
- Пересылка в этот сценарий не попадает: признак тот же, что у обработчика пересылок GitHub (`forward_origin` или `forward_date`). Свободный текст это слова самого наставника; чужой текст (скрытый автор, другой участник, канал, чат) не может стать заметкой о прежнем «активном участнике». До 02.10 это держал только порядок роутеров (обработчик пересылок GitHub стоит раньше и забирает любую пересылку), теперь задано фильтром обработчика. Пересылка с командой идёт по [02.19](scenario-02-19-mentor-note-dm.md), где автор определяется по пересылке.
- Наставник сегодня — один и тот же человек, что и пилот, использующий бота лично (марафон, лента и т.д.). Узкое окно риска: если он написал что-то личное боту в те же 2 часа после наставнической пересылки, ПОКА ни одно состояние диалога (машина состояний марафона/ленты) не ожидает от него ответа — иначе более ранний роутер (`workshop_router` и т.п., зарегистрирован раньше `mentorship_router` в `handlers/__init__.py`) уже заберёт сообщение первым, этот хендлер до него не дойдёт. В логах инцидента 28.09 оба захода шли с `state=None` — то есть ровно в тот момент, когда обычная маршрутизация и так ничего не ждала от этого текста.
- `SkipHandler` (не голый `return`) при отсутствии активного участника — обязателен: этот хендлер стоит в общей цепочке роутеров до SM/fallback, голый `return` остановил бы маршрутизацию и молча проглотил бы личное сообщение КАЖДОГО пользователя бота. Тот же паттерн уже используется в `handlers/hermes.py` по той же причине.

## 3. Известные ограничения

- То же ограничение TTL/in-memory, что у [02.19](scenario-02-19-mentor-note-dm.md) §3 — активный участник не переживает рестарт/redeploy бота.
- Если наставник в узком окне (см. §2) пишет боту личный текст, не связанный с наставничеством, бот предложит сохранить его как заметку — придётся нажать «Отмена». Не решение пилота вводить более точное различение — принятый компромисс минимального варианта.
